## What changed

- **The forge judges each commit that can land once** (S02). The `push`
  trigger's branch list is the trunk alone; the request's run judges the
  request head. A unit on a path branch is judged by the writer's bare
  gate, and by the request's run once one is open — which this path then
  opened as a draft at S02, so every unit after it was judged on the
  exact head.
- **A red run writes its own reading** (S01, S02). `cairn-postmortem`
  prints, for one path or every path record, the registration commit
  against `base_commit`, the administrative commit the branch declares,
  the definition of done's digest against the acceptance in force, each
  step record against the blob that added it, and — with a token — the
  red runs of a branch and the time a request stayed open. Facts only:
  it closes on a line saying where the judgement is and makes none. A
  workflow step runs it on the checker's own failure, into the log and
  onto the request, committing nothing.
- **This repository's suite runs under its own name** (S02).
  `cairn-test` before the checker, with `npm test` kept as its alias so
  the bootloader's command list stays true. The kit installs no suite and
  its workflow runs no test step.
- **The two tools that speak to the owner say what 1.1 decided** (S05).
  `cairn-audit` prints the description in the order the owner reads —
  three plain lines and the surface, then the definition of done item by
  item led from the record, then the ledger. `cairn-active` reports a
  roadmap register still carrying the installer's row while any path is
  registered.
- **The six sentences paths 1 and 2 owed** (S06), one each and naming no
  record: the unit skill reads a red run's post-mortem and reads the
  request's run where there is one; it says how a repair declares that it
  supersedes an edited step record, with the path template giving the
  shape and the commands; the open skill names the two answers to an
  overlap; the close skill says the integrating commit is one commit for
  one path.
- **The tools' module note describes them as they are** (S07).

## What this path got wrong, and how it was caught

- **The gate certified a protection this repository does not have.** S02
  mapped `GITHUB_TOKEN` into the checker's step, which is the fifth debt
  path 2 handed over. The draft request's first run then printed *forge
  enforces everything these records name* while the trunk's ruleset
  carries a role that bypasses it always. A workflow's token may not read
  a ruleset's bypass list and the forge ELIDES the field rather than
  refusing it, so `forgeGaps` read silence as safety. S03 took the token
  back out: *forge not read* is the honest line. **Item 2 of the
  definition of done closes knowingly unmet**, with S03 as the reason and
  the owner's ruling in the chat.
- **`depends_on` was written backwards** in the open skill's owed
  sentence — on the path that lands first rather than the one that
  waits — and the gate would not have caught it, because
  `writesOverlaps` falls silent when either path declares the other. A
  fresh reader found it.
- **`current_step` had said `S01` since registration** (S08). That field
  is how the `review` rule picks which step record to read, so for seven
  units the gate re-read S01's review and passed, and the `work-unit`
  rule was satisfied by S01's block for the same six. Nothing was
  missing; the gate was not doing what it says. It surfaced because the
  closure wanted to move the field and may not.
- **A dangling sentence sat in the tools' module note** from S03 to S07,
  through three green runs. No gate reads prose, and a document is only
  checked when a reader is handed it.
