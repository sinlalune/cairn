# CP-CAIRN-001 — Cairn 1.0

Opened 2026-09-02 from the genesis commit, seeded from Atomik with the 0.2
protocol, with the manifesto and the convergence record as its input and the
owner's rulings on section 4 as its definition of done. Closed 2026-09-03 at
candidate `fdb73f1`, the second — the first, `7c0e9ce`, was voided by the
review of pull request #2 — after nine units, each pushed and green.

## What changed

- **The specification is on the six stages** of the chronology, 5,630 words
  from 17,455, with 31 own concepts beside 21 borrowed.
- **The rules are twenty-four**, nineteen blocking, every blocking one proved
  by a fixture that builds a real repository and breaks it on purpose; the
  0.2 checker had 38 names and 8 fixtures.
- **A path is one folder**: opening acceptance inline, a resume section in
  place of the brief, `depends_on:` projected as the unblocked view, two
  routes, no folder logs.
- **The pull request is the closing record**, its approval the acceptance;
  `manual-git` keeps one closing record in the path folder. The checker
  proves only what Git holds.
- **Five skills** carry the procedures, each under a thousand tokens; the
  operations page became their reference files.
- **One command** — `cairn`, of the `cairn-protocol` package — installs a
  26-file kit that links the specification at its commit, inspects and
  updates by lock digest, and adopts a repository that carries the protocol
  without a lock. Atomik at `46bdd11` adopts; its gate then names five links
  of its own to fix.
- **Four documentation layers**: the manifesto's edited edition, the README
  with three quick starts, the specification, and a site that renders them
  with Mermaid, deployed to GitHub Pages from the trunk.
- **Every weight target bound**, measured by the tools: the index under
  8,000 words, the entry chain under 3,000, the kit under 30 files, two
  protocol files per lightweight unit. The greenfield pilot runs from
  install to `done` on both transports as a command and a test.

## What the closure itself found

The review of the first candidate found four defects, one of them a release
blocker: the packaged command could not run without a host configuration.
All four were fixed with a test each in S09, the candidate was voided and
produced again, and the review repeated — the sequence the specification
says, run on the protocol's own repository. The calendar moving during the
path made the fixture harness's dated records drift, and the rule that
noticed was kept.

## Deviations, stated

- The npm name `cairn` belongs to another package; the package is
  `cairn-protocol` and its binary `cairn`, by the owner's decision.
- The S04 unit landed in two commits, by a staging error, on a branch that
  is never rewritten; the step record says so.
- The cold-resume trial was not rerun against the resume section; it is a
  1.1 measurement.

## What comes next

The tag `1.0.0` on this integration, the package published from it, the
first queued project as adopter number one, and its friction as the 1.1
agenda.
