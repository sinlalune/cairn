# CP-CAIRN-008 — the readings that must not lie

Opened 2026-09-14 on the owner's go-ahead in the chat, registered directly
on the trunk as `99554f2`, governed by the 1.1 page, path 3's S03 and
journal entry and four records at their blob ids. Closed 2026-09-15 at
candidate `bd786f9`, the second — the first, `a2489a9`, was voided when a
review of it found a sentence this path had written to be false. Ten units,
each pushed and green, each read by a fresh context and its fixes read once
more. The opening acceptance was amended twice, both on 2026-09-14. The
administrative commit `e46b81a` stood on the branch with its check green
before the merge was asked for. Merged by the owner as `22f9895` through

## What changed

- **A reading the forge withheld is reported as unread, never as an
  answer** (S01, S02). ADR-026 decision 1, and the checker made to keep
  it. GitHub returns a ruleset's `bypass_actors` only to a caller with
  write access and elides the field otherwise; a workflow's own token can
  never have it. `forgeGaps` read that silence as an empty list and the
  profile line printed *forge enforces everything these records name* over
  a trunk whose ruleset carries an always-bypass role. `forgeGaps` now
  returns `{ gaps, withheld }` and never sums them, `readForge` names the
  half it could not read, and the line prints read, withheld and
  unenforced. `GITHUB_TOKEN` returned to the checker's step on the
  strength of it, closing item 2 of path 3's definition of done.
- **The review rule reads the unit under review** (S01, S03). ADR-026
  decision 2. It selected by `current_step` over a list sorted by ordinal,
  so the field could only ever point at a unit OLDER than the one just
  written; on path 3 six units' review sections were never read. The
  `find(…) ??` is gone and `current_step` selects nothing.
- **One commit for one path, and the merge-object refusal by transport**
  (S01, S03). ADR-026 decisions 3 and 4. The checker refused two paths in
  one *commit* while ADR-008 decision 2 said *never two paths in one
  request*; the narrower reading is the one that binds, and that sentence
  is superseded. The refusal of a merge object carrying `done` now binds
  on `pull-request` integration alone — on `manual-git` that merge IS the
  integrating unit, which the close skill had prescribed and the checker
  had refused.
- **Path 3's four leftovers** (S04). The conformance page's stale sentence
  on a supersession's writer half; the close skill and its reference
  saying what the checker refuses by transport; the post-mortem importing
  the checker's readings instead of repeating its Git plumbing — 103 lines
  shorter, output byte-identical across every path record.
- **The gate reads the integration it judges** (S07, S09). Found by a bot
  review of the first candidate, which caught one false sentence; reading
  it found the cause larger. No run compared the trunk across an
  integrating commit, on either transport: a bare trunk run resolves no
  base and sees the working tree, and the workflow based a push run on
  `origin/main`, which after that push already names the pushed commit.
  Every integration this repository ever landed was judged against `0
  changed file(s)` — `transition`, `acceptance`, `scope-digest` and
  `journal-entry` never judged an arrival, and `journal-entry` exists for
  nothing else. The workflow, and the one the kit generates, now base a
  request on its target branch, a trunk push on the commit it replaced,
  and a path-branch push on the trunk. Beside it a new blocking rule,
  `comparison`, standing behind *One invocation, one verdict* — a stated
  requirement that carried three fixtures and no predicate — reporting a
  base that cannot be compared with this commit and, off a path branch,
  one that already contains it.
- **The `ready` behind an integrating commit is on any parent** (S08,
  S10). ADR-027, promoted from this path's own S03. `integrationState`
  read the FIRST parent, which is a `pull-request` shape; on `manual-git`
  the `--no-ff` merge is the integrating unit and the branch's `ready`
  sits on the second, so that transport could not close honestly. One
  expression over the parent list already computed. Both halves of
  `manual-git` integration are now decided.

## What it leaves

One debt, knowingly, and one correction to its own record. ADR-027's first
draft argued that widening to any parent admits "nothing older"; that is
false, because a merge parent carries an arbitrarily stale record. A
withdrawn closure — `ready` → `running` is legal — can be re-integrated
from a branch still holding the old `ready`, which the first-parent
reading refused. A second draft excused it as outside chapter 5's remit;
that was false too, since staleness and coordination error are two of the
four things the checks claim. The record retracts both in its own text and
accepts the gap on cost: closing it means dating each parent's last state
change. A fixture named `KNOWN GAP` pins the shape as NOT refused and
tells whoever makes it refuse to delete the fixture and the paragraph
together.

Row 4, the kit, inherits one line of `tools/cairn.mjs` that this path's
second amendment took. Row 6, the release, is what remains of 1.1.
