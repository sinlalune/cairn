# CP-CAIRN-017 — forward plan

Read when planning, never before every step. Each item is one work unit.
A measurement, a quick start, a build or an update is proved by its
output in the step, never by description.

1. **S01 — the milestone rule's record.** ADR-045, promoted from path
   4's journal entry, superseding ADR-031 decision 2's *that path's* for a
   milestone; ADR-031 marked, the 1.2 page amended in place, the records'
   index; the backlog item deleted.
2. **S02 — what the backlog and the reports owe the adopters.** The
   `steps/` folder carried or created (the open skill); `current_step`
   set in the unit skill's fifth movement, with the two sentences of
   Atomik's closing report — print, don't remember; the review before
   the commit; the bootloader template's two lines; `conceptLinkTargets`
   resolving against the folder and the declared root, one fixture; the
   four backlog items deleted.
3. **S03 — the changelog.** `CHANGELOG.md` with 1.2.0's section: the
   adopter repairs absorbed and not, by the three adopters' path ids, read
   from their registers; what the release changes for an adopter, in the
   pointer page's names; one line per template changed since 1.1.0
   (ADR-039, ADR-015 decision 2); ADR-015's table and the register's 1.2
   row cleared of *pending* (ADR-031 decision 3).
4. **S04 — the counts written once.** The budget table measured at 1.2.0
   by the tools, beside the two earlier columns (ADR-022 decision 2); the
   kit row, the README, the tools' module note and the installer's header
   comment linking the row and restating no figure (ADR-031 decision 1).
5. **S05 — the README and the site.** The surfaces of 1.2 in the order a
   newcomer meets them, every sequence 1.2's, the quick starts run
   (ADR-023 decision 1, ADR-012); the site built from the candidate, its
   hard-coded lists matching the README; `docs/modules/site.md`.
6. **S06 — this repository updated with its own kit.** `cairn update`
   run here at the candidate's package, the report quoted, edited files
   kept and listed, declinations with reasons, the pointer page and the
   lock at 1.2, `status` clean.
7. **S07 — the treated notes and the version.** `feedbacks/1.2/` and its
   index naming what answered each line, thirteen notes moved with their
   links once S02 has answered the two Atomik notes' open asks
   (ADR-038 decision 3); the 1.2 page's opening sentence; `package.json`
   at 1.2.0; the register's 1.2 row and row 5 naming this path.
8. **S08 — the candidate.** Trunk merged in, gates bare; the register
   restored before the administrative commit; the fresh-context coherence
   read in the request's description; the owner opens the site and the
   README and runs one quick start; the merge. After the integrating
   commit: the tag `1.2.0` on it, the package published by the owner, the
   three adopters' updates named as the next paths in their repositories.

## What the units must not do

Change a skill, a rule, a tool or the installer beyond the lines S02 names. Write a
figure of the kit anywhere but the budget table. Fix here what the update
of this repository finds wrong — write it down instead.
