# CP-CAIRN-004 — forward plan

Read when planning, never before every step. The records follow the three
themes the twelve answers fall into, so a reader holding the note can find
the record for any answer; the 1.1 page and the register come last because
they name every record.

1. **S01 — ADR-021, what a session writes for its reader.** P1, P5, P6:
   one line in the bootloader, beside the concept-note rule of ADR-011,
   saying an explanation is written for the reader who is learning it —
   the plain meaning first, the failure it prevents, the shortest example
   — and stops there (P1); the request's description and the path
   record's plan open with three plain lines — what it does, why it is
   the least, what it does not do — and a link to the surface page, the
   ledger following unchanged (P5); a question to the owner — at the plan
   review, the try before the merge, a red run, an accepted race — is put
   in the chat and well signalled as what it is, in the owner's words,
   with what happened and the ways to go on (P6). Names `AGENTS.md` as
   the kit writes it in `tools/cairn.mjs`, the request template, `cairn-audit`,
   `spec/reference/path-template.md`, `cairn-open` and `cairn-close`, the
   post-mortem tool's output. Options refused: a stance skill for
   explanation, the manifesto only, the ledger only, free prose.
2. **S02 — ADR-022, the learning note, the learning session and its
   offer.** P2, P3, P4: a learning note is a concept note with an order,
   living in `docs/concepts/learning` and linking the concepts it rests
   on in sequence, chapter 6's paragraph changed to say so and ADR-011
   decision 2 extended, not superseded (P2); a sixth skill, `cairn-learn`
   — what it reads first, how it explores with the user by prompting,
   what it writes, how it ends — named by the bootloader's entry route and
   by the pointer page of ADR-013, with the kit's file budget paid by a
   named removal or re-measured by the release path (P3); a unit that
   explains an abstraction writes the concept note, says in its step that
   a learning session was offered on it, and the session runs later in
   its own context, one sentence in `cairn-unit` step 2 (P4). The one
   answer of the note that adds a file; the manifesto's test weighed.
   Options refused: a learning root of its own, no learning notes, a
   bootloader sentence in place of the skill, the note only.
3. **S03 — ADR-023, the pages a reader meets.** P7 to P11: the adopter's
   README says what the project is in a paragraph and lists the surface
   pages, promotion units that add a surface add its line, the close skill
   says so (P7); promotion produces one workflow page per flow that
   crosses components, with a diagram, refreshed by the unit that changes
   the flow, chapter 3 gaining the output and a template (P8); the
   architecture template asks for one Mermaid diagram of the components
   and the direction ADR-019 states, and the surface page template asks
   for one worked example before anything else (P9); Cairn owns no API
   page and names none — the agent creates and maintains the API
   documentation of an API surface, in the owner's words, and the surface
   page links it (P10); nothing more on where the senior searches, the
   folders' indexes are the map, kept as today (P11). Options refused:
   the documentation index as the page above, no page above, a flow
   section in the architecture page, no workflow page, diagrams nowhere
   in particular, the ecosystem's generated reference alone, a Cairn API
   page, the journal said in two places.
4. **S04 — the 1.1 page, the index and the register.** The architecture
   page amended with a section on what a session writes and what the
   documentation plane gains, each sentence naming its record and marked
   *since 2026-09-09*, *promoted from* links to the note and the
   statement at their pinned blob ids, the manifesto's edition cited for
   the pedagogy section, no 1.1 record superseded; the index of
   `docs/adr/` and of `docs/architecture/` refreshed; the register's rows
   1, 4 and 5 widened with the records and surfaces, no path opened.
5. **S05 — the candidate.** Trunk merged in, gates bare, the request
   opened with three plain lines first, the definition of done item by
   item, then the coherence audit; the owner reads the pages before the
   merge.
