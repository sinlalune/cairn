# CP-CAIRN-007 S05

### S05 — the two tools that speak to the owner — **COMPLETE**

#### Plan

Make the request's description open the way the owner reads, and make
the live view say when the roadmap register was never written.

`cairn-audit` prints the description in the order the template already
gives: what the path did, why it is the least, what it does not do, and
the page a newcomer opens for the surface it changed
([ADR-021](../../../../docs/adr/ADR-021-what-a-session-writes-for-its-reader.md)
decision 2); then one line per item of the definition of done, read from
the record, each with a place for the unit that advanced it and the
command or page that shows it
([ADR-018](../../../../docs/adr/ADR-018-two-sentences-of-the-cycle.md)
decision 2); then the ledger, unchanged. `cairn-active` reports a
register that still carries the installer's row while paths are
registered
([ADR-008](../../../../docs/adr/ADR-008-housekeeping-with-no-choice-in-it.md)
decision 5).

Definition-of-done items advanced: the third and the fourth.

Type `implementation`: two tools, their tests, this step. Failing tests
first for both, and a fixture for the advisory — a reading that is right
and reaches nobody reports nothing, which is what S01's first attempt at
a wiring test proved about itself.

Deliberately not in this unit: `.github/pull_request_template.md`, which
path 1 already wrote in this order and which this unit matches rather
than edits; the `cairn-close` skill's sentence naming the item-by-item
answer, which is the owed-sentences unit; the module note, which the
next-but-one unit rewrites against the whole candidate.

- **`tools/cairn-audit.mjs`**: `definitionItems` reads the record's
  `## Definition of done` through the checker's own
  `resolveScopeSection`, joins each item's wrapped lines, and leads it
  with its first hundred-odd characters cut on a word — the record holds
  the item whole and the digest seals it there. `requestDescription`
  gains the two sections above the ledger and takes the items as a
  parameter, so the shape is proved without a repository; `main` reads
  them from the record it already resolved.
- **`tools/cairn-active.mjs`**: `registerAdvisory` reads the register's
  text and the number of live paths, and returns a line or `null`. A
  line, never an exit code: what milestone a project has is the owner's
  to write. Nothing is said before the first path is registered, and an
  unreadable register is not reported as a register with a placeholder
  in it.
- **`tools/cairn-audit.test.mjs`**: the order of the six headings, the
  items read from a record whose items wrap and one of which is long,
  the empty case, and that the tool's markers are the request template's
  own.
- **`tools/cairn-active.test.mjs`**: the predicate's four answers, and a
  fixture that installs a real kit repository, proves the advisory
  silent with no path, registers one, proves it printed, fills the
  register and proves it silent again.

#### Review

First read, a fresh context given this unit's diff and the two criteria,
the ladder and correctness, and nothing else. Fifteen findings:

- `correctness:` `lastIndexOf(' ', LEAD)` answers `-1` for an item whose
  first hundred characters hold no space — a long backticked path is the
  real case — and `slice(0, -1)` then returns the whole item minus its
  last character, which is the opposite of a lead. **Fixed**, with the
  case pinned.
- `correctness:` a cut landing inside a backtick span left it open, and
  the next backtick on the rendered line closed it around the writer's
  own blanks, so the two places they fill vanished into a code span —
  the exact thing the comment above the cut claimed never happened.
  **Fixed**; the second read then moved the repair to the right side of
  the ellipsis.
- `correctness:` the angle-bracket markers do not survive the forge. A
  bare `<unit>` matches an HTML open tag and the sanitiser strips it, so
  the owner would have read three empty bullets and *advanced by — shown
  by* — a blank that reads as an answered one, which is the failure the
  section exists to end. **Fixed**: every blank is backticked, in the
  tool and in the template.
- `correctness:` the template's own comment said the tool prints *the
  ledger below, from `## Candidate` down* and that the two sections above
  are the writer's — false the moment this unit moved the tool's output
  up. **Fixed**, and `writes:` widened by that file: a template that
  describes this tool is part of this tool's surface, and leaving it
  wrong would have had a writer paste a second copy of a section they had
  just written by hand.
- `correctness:` the kit's generated `requestTemplate()` has none of
  this, so *a writer meets the same shape* is true here and false for
  every adopter — **fixed** in the claim, which now says *this
  repository's template*; the kit's generator is the roadmap's row 4,
  which S04 gave ADR-018 decision 2 and which this unit does not write.
- `correctness:` the register reading was fed LIVE paths while its own
  sentence says *registered*, so on the repository it was written for —
  where the sixteen paths had all closed — it would have said nothing.
  **Fixed**: every record counts, and the wiring fixture's path is
  `done` so the case is the real one.
- `correctness:` continuation absorbed anything that was not a checkbox,
  so a paragraph or a table after the list joined the last item.
  **Fixed** by requiring an indent; the second read then showed the
  stop was worse than the swallow.
- `correctness:` `*` and `+` task-list bullets read as no items at all,
  sending the writer to look for a section that is right there.
  **Fixed**.
- `correctness:` `paths` was unguarded where `register` was guarded, so a
  caller omitting it printed *while undefined paths are registered*.
  **Fixed**.
- `correctness (test):` the one-shape assertion read this repository's
  template rather than the exported generator, which is the one place it
  could not catch the adopter-facing gap — **accepted**, and the claim
  narrowed instead: the generator is another row's, and a test asserting
  what it does not yet do would have to be deleted by the path that makes
  it true.
- `correctness (test):` `!line.includes(PLACEHOLDER)` proved nothing —
  that literal could never appear in a fixed format string. **Fixed**
  into the contract it was reaching for: the new sections carry no
  placeholder, and the ledger still does.
- `correctness (test):` the only length bound was a loose magic number
  and nothing exercised a long single token. **Fixed**: a named ceiling,
  written in the test rather than imported, and both edge cases.
- `correctness (test):` `--check` reports the advisory and nothing tested
  it. **Fixed**, though the first fix did not run `--check` at all —
  see below.
- `correctness (test):` the plural branch was unreached. **Fixed**.
- `shrink:` the record was read twice per run, and `items` was computed
  on both transports and printed on one. **Fixed**: `currentPath` carries
  the text it already read, and the items are parsed inside the
  `pull-request` branch — the closing record on `manual-git` has no
  item-by-item section, because ADR-018 decision 2 is about the request's
  description.
- `shrink:` `join(REPO, REGISTER_FILE)` computed twice, and the rationale
  written out three times across tools and tests. **Fixed**: one join,
  and the comments point at the record instead of restating it.

Second read, a fresh context given only the diff of those fixes and the
same two criteria, as ADR-017 decision 3 bounds it. Twelve findings:

- `correctness:` the assertion that the closed path is *not in the live
  view* never looked at the view — it read stdout, which never carries
  the view body, so both disjuncts were decided by the tool not printing
  it. **Fixed**: it reads `ACTIVE.md` in the fixture.
- `correctness:` the `--check` assertion did not exercise `--check`: the
  run before it had made the view current, so the command took the early
  exit. **Fixed**: the view is made stale first, and because `--check`
  then exits 1 the advisory is read off the failure — and the claim that
  it writes nothing is now asserted, not asserted-about.
- `correctness:` both truncation cases passed on an empty string, in the
  two cases the test exists for. **Fixed**: each asserts the lead begins
  with the item's own first words and says it was cut.
- `correctness:` the template still carried five bare blanks — the
  candidate object ids, the record, the reviewer — and the sentence added
  to that very file claimed they were all backticked. The ledger fields
  are where a stripped blank is worst: a candidate line naming no
  candidate. **Fixed**, all five, and the nested blank inside the digest
  line rewritten so it needs no nesting.
- `correctness:` the bare-blank guard was pointed at the one artefact
  that no longer contains a `<`, and its character class could not match
  `<ID>` anyway. **Fixed**: it runs over the template line by line, and
  over the description.
- `correctness:` *a wrapped item is indented* is not how markdown wraps —
  lazy continuation needs no indent, and the `break` would then drop
  every item after the wrap, where the old code mis-joined one line.
  **Fixed** to a skip: an unindented wrap costs a lead a few words and
  never costs the reviewer an item.
- `correctness:` the two rules disagreed about indentation — load-bearing
  for a continuation, ignored for a bullet — so a nested sub-checkbox was
  promoted to a sibling item and renumbered everything after it.
  **Fixed**: an indented checkbox belongs to the item above it.
- `correctness:` the repair backtick was appended after the ellipsis, so
  a mid-token cut rendered as a closed span with the ellipsis inside —
  a truncated command reading as a whole one, which is the fault the
  first read named. **Fixed**: the span closes before the ellipsis.
- `correctness (minor):` the template's item slot is backticked while the
  tool emits the lead bare — **accepted**: in the template that slot is a
  blank, and in the output it is the item's own words. The marker list
  does not claim it.
- `correctness (minor):` the negative on the template's old sentence
  passes for any rewording and for an empty file — **fixed** into a
  positive match on what it says now.
- `shrink:` the registered count parsed every record a second time, when
  `collectPaths` already builds exactly that set, deduped by id.
  **Fixed**: `collectPaths` returns the live paths and the registered
  count from one parse, and the call sites say which they want.
- `yagni:` the `!(paths >= 1)` guard and its test exist for a call shape
  nothing makes — **half accepted**: the guard stays, because it is one
  character and closes a hole the first read found, and the test for it
  is **deleted**, because a test of a call nobody makes is a test of
  nothing.

The fixes above are not read a third time.
