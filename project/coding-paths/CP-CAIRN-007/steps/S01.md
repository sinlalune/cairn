# CP-CAIRN-007 S01

### S01 — the post-mortem tool — **COMPLETE**

#### Plan

Add `tools/cairn-postmortem.mjs` and its test: for one path or for every
path record in the repository, the six readings
[ADR-014](../../../../docs/adr/ADR-014-two-tools-of-1-1.md) decision 1
lists — the registration commit and its parent against `base_commit`,
the administrative commit against the shape closure may take, the
definition of done's digest recomputed against the acceptance in force,
each step record against its adding blob, the red runs of a branch and
the time from a request's opening to its merge when a token lets the
forge be read — printed as a table of facts with no judgement in it
([ADR-021](../../../../docs/adr/ADR-021-what-a-session-writes-for-its-reader.md)
decision 3), and the script `cairn-postmortem` in `package.json`.

Every reading the checker already computes is IMPORTED from it:
`statusCommit`, `closureFieldErrors`, `resolveScopeSection`,
`scopeDigest`, `openingFromRecord`, `recordOriginFromFollowLog`,
`preservesAppendOnlyRecord`, `isAppendOnlyStepRecord`,
`resolveBranchRef`, `githubSlug`, `githubRequest`. The checker is read
and never written.

Definition-of-done item advanced: the first.

Type `implementation`: the tool, its test, the package script, the tools
table of the module note, this step. Failing test first — every reading
is a pure function of what Git and the forge answered, and the two forge
reads take their `request` as a parameter, so the suite proves them
against payloads and never over the network.

Deliberately not in this unit: the workflow that runs the tool on a red
run (S02); the audit and live-view tools (S03); the owed sentences of
the skills and the template (S04); the module note's prose, which S05
rewrites against the whole candidate — this unit adds the one table row
the unit skill's *affected module note* requires and no more; the kit's
manifest in `tools/cairn.mjs` and the layout reference, which are path
4's.

Observed and carried anyway: `package.json`'s `files` list is what npm
packs, so a package naming a script whose file it does not ship would
hand path 4 a kit manifest it cannot install from. The entry lands here,
with the script, in a file this path already writes.

#### Work

- **`tools/cairn-postmortem.mjs`**, new. Six readings, each a pure function
  of what Git or the forge answered: `registrationReading`,
  `closureReading`, `scopeReading`, `stepsReading`, `redRunsReading`,
  `requestsReading`, with `duration` and `renderReadings` beside them and
  `NO_JUDGEMENT` as the closing line. The two forge reads, `readRedRuns`
  and `readRequests`, take their `request` as a parameter, as
  `readForge` does in the checker. The impure half resolves the path
  records, the trunk and branch histories, and the step records' adding
  blobs, and calls nothing of the checker but its exports:
  `statusCommit`, `closureFieldErrors`, `resolveScopeSection`,
  `scopeDigest`, `openingFromRecord`, `recordOriginFromFollowLog`,
  `preservesAppendOnlyRecord`, `isAppendOnlyStepRecord`,
  `resolveBranchRef`, `githubSlug`, `githubRequest`,
  `TRUNK_BASE_CANDIDATES`. `--path <id>` reads one path, `--branch
  <name>` the path of a branch — the form CI has, where HEAD is detached
  — and neither reads the whole repository, which is what a run off a
  path branch gets. No reading reaches an exit code.
- **`tools/cairn-postmortem.test.mjs`**, new: ten tests over the pure
  half and the two forge reads. The adversarial ones are the reading of
  a record that no longer carries its adding blob, the reading of a
  branch this checkout has no ref for, the forge answering `HTTP 403`,
  a token absent with a `request` that throws if it is called at all,
  and the table asserted to contain no question mark and none of
  *should*, *must*, *recommend*, *wrong*, *violat*, *fail* — the
  assertion that fails the day a reading begins to judge.
- **`package.json`** names the script `cairn-postmortem`, and `files`
  ships the tool.
- **`docs/modules/application.md`** gains the tool's row in the table and
  its name in the frontmatter description.

#### Review

First read, a fresh context given this unit's diff — the tool, its test,
the package script and the module note row — and the two criteria, the
ladder and correctness, and nothing else. Fifteen findings; each with its
disposition:

- `correctness:` `reachable` was true for EVERY record whenever HEAD is
  detached, because `resolveBranchRef` answers `head` unconditionally
  there, so `source !== 'head' || detached` short-circuits. That is
  exactly the CI request run the comment was written for, where the
  reading would then have been about the wrong branch — **fixed**: HEAD
  answers for a branch only where HEAD is that branch, which is the
  detached head the run names with `--branch`.
- `correctness:` the sentence *no branch declared* was passed to the
  forge as a branch name, so a record with no branch got `no red run on
  this branch` — a positive fact about a branch that does not exist —
  **fixed**: a third *not read* reason, beside no token and not GitHub.
- `correctness:` the committed-step filter read `git ls-files
  --error-unmatch`, which answers about the INDEX. Demonstrated on this
  very unit: the staged `S01.md` printed as *0 of 1 preserve ... has an
  adding blob this checkout cannot read* — **fixed**, the question is put
  to history, and only of a record whose adding commit was not found.
- `correctness:` the adding blob was read without the guard
  `tools/cairn-check.mjs` puts on `--follow`: rename detection pairs two
  step records written from one template, so a new `S02.md` is reported
  as a rename of `S01.md` and the SIBLING's blob is read as its own —
  a fabricated rewrite, in the one document that exists so that nobody
  argues from a fabricated fact. **Fixed**, the checker's guard carried
  over with its reason, and the fixture below reproduces the pairing.
- `correctness:` `ready` and `done` were bucketed together while the
  range is the branch's and `done` is declared on the trunk, so the
  `done` half was structurally unreadable — **fixed**, twice: first by
  narrowing to `ready`, which the second read showed blinds the tool to
  a branch that wrongly declared `done`; the reading now watches for
  either ON THE BRANCH and names which it found.
- `correctness:` `GITHUB_TOKEN ?? GH_TOKEN` lets an empty string win, and
  an unset secret in a workflow IS the empty string — **fixed** to `||`,
  which is what the checker reads the same two names with.
- `correctness:` `closureFieldErrors` answers `[]` for a comparison it
  could not make, so an unreadable side rendered as *moving only the
  fields a closure may move* — **fixed**, an unreadable side is said.
- `correctness:` the path root was read without a guard, so a repository
  with no `project/coding-paths/` threw instead of reaching the honest
  empty answer already written below it — **fixed**.
- `correctness:` `per_page=20` truncated the request list in silence —
  **fixed**, and the second read sharpened it: a full page is a page with
  more behind it, and the reading says so.
- `correctness:` `--path` with nothing after it read as `--path` not
  given, so a typo swept every record — **fixed**, refused with an exit
  code.
- `shrink:` the header claimed nothing is recomputed that the checker
  computes, while `git`, `recordShapes`, `recordHistory` and the closed
  statuses are copies of private helpers of it — **half fixed, half
  refused**. The claim is fixed: it now says the READINGS are imported
  and the Git plumbing around them is repeated, and names that repetition
  as the one place the tool can drift. Exporting the four from
  `tools/cairn-check.mjs` is refused here: item 7 of this path's
  definition of done holds that file byte-identical, and an `export`
  keyword is a byte. The debt is in *Tried and rejected* and goes to this
  path's journal entry.
- `shrink:` every candidate commit's record was read four times, twice by
  the filter and twice again for the shape — **fixed**: one memoised read
  per resolved object, which also makes the parent of one commit and the
  previous commit of the range one cache entry.
- `shrink:` the whole impure half had no coverage, and the repository's
  own fixture harness exists for exactly that — **fixed**, see below.
- `correctness:` `assert.ok(!out.includes('?'))` sat on `renderReadings`,
  which is a join and can never introduce one, so it passed whether the
  unit worked or not — **fixed**: the property is asserted over every
  branch of every reading, the forge's four *not read* reasons included.
- `correctness:` `package.json` now ships the tool in `files` while the
  kit's manifest in `tools/cairn.mjs` does not install it — **deferred**
  to coding path 4, which owns the manifest and the installed scripts and
  is named for it in *Deliberately excluded*. Shipping it is what makes
  that path possible: reverting the entry would leave path 4 needing
  `package.json`, which its writes column does not carry.

Second read, a fresh context given only the diff of those fixes and the
same two criteria, as ADR-017 decision 3 bounds it. Eleven findings:

- `correctness:` the first read's fixture test asserted NEITHER bug it

- `delete:` `stepRecordOrigin` is a verbatim copy of the checker's

- `correctness:` the registration assertion accepted either outcome, so

- `correctness:` the unreadable-side guard returned on the first such

- `shrink:` `closureReading` took the list twice — **fixed**.
- `shrink:` `stepsOf` probed history for every record and then asked for

- `shrink:` `resolveBranchRef` was called for a record with no branch and
