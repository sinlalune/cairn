# CP-CAIRN-011 — forward plan

Read when planning, never before every step. Nothing here decides; every
number is counted by a tool and every sentence made true is one 1.1 made
false. A quick start or a build is proved by running it and pasting the
output into the step. Each unit runs the review movement with the
reader's line first, and sets `current_step` to the unit whose block is
in the commit.

1. **S01 — the README.** What Cairn is in one paragraph, the surfaces
   one line each (ADR-023 d1, ADR-012); six skills, the rules as the
   catalogue counts them, five movements, the files `init` installs as
   the lock counts them, `manual-git` registration; the three quick
   starts run against the kit at this commit and their output kept; the
   *Weight* section pointing at the conformance page.
2. **S02 — the site.** The build run from the candidate; the *Start*
   section and any hard-coded list agreeing with the README; the sixth
   skill projected.
3. **S03 — the weight measured at 1.1.0.** The conformance page's budget
   table gains the 1.1.0 column: the specification's words, the entry
   chain's words, the kit's files on each profile with no target, the
   files a lightweight unit writes by `tools/cairn-pilot.mjs`; each
   target that has one reported bound or not (ADR-022 d2).
4. **S04 — this repository updated with its own kit.** `cairn update`
   run here, the report quoted; pristine files rewritten, edited ones
   listed with what the release changes; `cairn/README.md` installed
   naming 1.1.0 and its commit; the lock refreshed; any file `update`
   would add that the binding does not want, named with the reason
   (ADR-013, ADR-015).
5. **S05 — the page's opening and the register.** The 1.1 page's opening
   sentence replaced and marked *since 2026-09-15*; `package.json` at
   `1.1.0`; the 1.1 milestone row *done* with the date and the tag to
   come, the *Cairn 1.2 — what 1.1 taught* row under it with *no path
   yet*, the five things and the first adopter's update as its agenda,
   the feedback file as its source.
6. **S06 — the candidate.** Trunk merged in, gates bare, the request
   opened with the description the audit tool prints; the administrative
   commit on the branch and its check green before the owner is asked;
   the owner opens the site and the README and runs one quick start.

**After the merge**, from the trunk: the integrating unit; the tag
`1.1.0` on the integrating commit; `npm publish` by the owner; the
journal entry naming both and the first adopter's update as the next
path, on Crumbz's register.
