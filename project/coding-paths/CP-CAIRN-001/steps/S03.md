# CP-CAIRN-001 S03

### S03 — one folder per path, and this record is the first one — **COMPLETE**

#### Plan

Make the path record the one folder the specification states: opening
acceptance inline in `index.md` and read there by the checker; a resume
section replacing the separate brief; `depends_on:` validated and projected as
the unblocked view; `foundation` folded into `full` and `emergency` dropped
from the tools' vocabulary; no folder logs in a path folder. Migrate this
path's own record to that shape in the same unit, as the worked example, and
write the reference pages and concepts to match.

Deliberately not in this unit: the closing shape. Closing acceptance is still
a session record and the coherence audit still an audit file, on every route,
until pull-request transport makes the request the record (S04); the two
closing reliefs of the lightweight route go with it. `cairn-init` still copies
the specification (S06).

#### Work

```cairn-unit
step: S03
unit: 03
type: implementation
verified: cairn-check, cairn-active --check, cairn-rules --write, test
```

- **Opening acceptance is read from the record.** `openingFromRecord` reads
  the last fenced YAML block under `## Opening acceptance`, so a scope
  amendment is a later block naming the one it supersedes; `schema` requires a
  `running` record in the change to carry a decision, an actor, a UTC time, a
  scope reference and a digest, and `scope-digest` reads the opening digest
  from the same block at closing. The session-record reading is gone, and so
  are the functions that did it.
- **`depends_on:` is the one edge.** `schema` requires it to be a list of
  canonical ids that name known records and never the path itself;
  `cairn-active` ends every live line with `unblocked`, or `waits on` the
  paths that have not reached the trunk — `done`, or archived as completed —
  computed from the whole corpus, so the view answers what to do next.
- **Two routes.** `ROUTES` is `lightweight | full`; `foundation` left the
  route and unit-type vocabularies with the surface predicate that served it,
  and `emergency` was never in the tools.
- **No brief, no folder log.** The lifecycle-record and closure-surface
  predicates no longer name a brief or a path folder's `log.md`; `cairn-init`
  no longer creates a briefs folder, and its project index says where the
  resume section lives.
- **The fixtures build the 1.0 record.** The harness writes a folder record
  with its opening acceptance bound to the digest the checker computes, and a
  step file under `steps/`; the `record-integrity` fixture and the parity test
  that needed a committed immutable record now rewrite an earlier byte of that
  step, which the adding-blob proof catches. Three `schema` fixtures cover the
  three ways an opening fails: absent, undigested, and a dependency on a path
  nothing declares. The suite is 225 subtests.
- **The reference pages say the 1.0 shape.** The path template was rewritten
  around the one folder, the opening block and the resume section, and the
  step file gained its plan and self-review parts; the handoff-brief reference
  was deleted and the handoff concept rewritten around the resume section; the
  human-records page moves the opening acceptance into the record and keeps the
  closing and audit files under a preface that names S04; operations, the
  repository layout, the execution protocol, the path convention and eleven
  concept pages lost their brief, session-opening and folder-log sentences.
- **This record is the worked example.** `index.md` carries the opening
  acceptance the session record recorded at registration — the same digest,
  and the original stays as the immutable record it is — a `depends_on: []`,
  a widened `writes:` naming the project index it edits, and a resume section
  that replaces the brief and the live header; the brief, its folder and the
  three folder logs are deleted. Four files per path: the index, the plan and
  two steps before this one.
- Rejected: a rule for the resume section. Its contract is a judgement
  measured by cold resume; a schema over prose is the proxy predicate the
  soundness note warns about, and `brief-schema` was that rule.
- Rejected: reading `depends_on:` transitively. One edge is what the
  convergence record asked for; a path that depends on a path that depends on
  another names both, or waits on the one that matters.
- Found and fixed: two concepts — `lightweight-path` and `work-ledger` — were
  linked only from the deleted brief page, so an installed repository reported
  them orphaned while this one did not; the normative text links them now.
  The fixture suite is what noticed, which is what it is for.
