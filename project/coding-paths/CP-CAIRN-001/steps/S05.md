# CP-CAIRN-001 S05

### S05 — the procedures ship as five Agent Skills, and the operations page becomes their reference files — **COMPLETE**

#### Plan

Ship Cairn's procedural half as Agent Skills: `skills/` with
`cairn-brainstorm`, `cairn-open`, `cairn-unit`, `cairn-close` and
`cairn-code`, one `SKILL.md` each under 5,000 tokens, loaded on demand. Cut
the operations page into the reference files of the three skills that run
commands, and delete it. `cairn-code` carries the decision ladder from section
3 of the convergence record. Install the skills with the kit, check their
links, and point the bootloader at them.

Deliberately not in this unit: a skill for integration alone (it is the last
part of `cairn-close`); the retained-host command sequences (a host plugin,
dropped from the reference files with a sentence saying so); `npx cairn`
(S06).

#### Work

```cairn-unit
step: S05
unit: 05
type: implementation
verified: cairn-check, cairn-active --check, cairn-rules --write, test
```

- **Five skills.** `cairn-brainstorm` writes the brainstorm and research
  notes of chapters 1 and 2 and knows when a note is ready for promotion;
  `cairn-open` writes the one-folder record with its inline opening
  acceptance and registers it before branching; `cairn-unit` advances one
  work unit as plan → change → self-review → verify, with the step record,
  the resume section, the bare gates, the explicit commit and the push;
  `cairn-close` takes one candidate through review, acceptance, the
  administrative commit, drift, integration on either transport, and
  cleanup; `cairn-code` is the stance — read the real flow, the seven-rung
  decision ladder, deletion over addition, the three-line cap, absorb the
  ecosystem, and what the stance refuses. Each `SKILL.md` is between 560 and
  700 words, about 750 to 930 tokens: a fifth of the budget.
- **The operations page is gone.** Its sequences are `reference.md` beside
  `cairn-open`, `cairn-unit` and `cairn-close`, on the two transports, with
  the retained-host sequences deleted in favour of one sentence: a host that
  declares `retained` runs its own retention procedure first. The execution
  protocol, the reference index, the path convention and the specification's
  closing section point at the skills instead.
- **The skills are checked and installed.** The checker's Markdown corpus
  includes `skills/` where it exists — a fixed name, like `spec/`, because
  it is the standard's shape rather than a role a host binds — so a
  procedure that links a page that moved fails `links` like any other, and a
  concept only a skill links is not an orphan. The kit copies the folder
  whole; the bootloader's start-here list gains the skills as its fifth
  line.
- Rejected: a `roots.skills` configuration field. The Agent Skills standard
  fixes the folder's shape, adopters install it at the root, and a field
  would be a migration every adopter pays for a name nobody would change.
- Rejected: writing the skills as summaries of the specification. A skill is
  a procedure to follow, not a text to learn; every sentence in one is an
  instruction or the one reason a reader needs to follow it, and the
  rationale stays in the specification one link away — the writing rule and
  instruction parity, applied.
- Rejected: keeping the operations page beside the skills' reference files.
  Two copies of a command sequence are where they disagree.
