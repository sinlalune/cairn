# CP-CAIRN-001 S07

### S07 — the four documentation layers: manifesto, overview and quick starts, the specification, and a site that renders them — **COMPLETE**

#### Plan

Write the two layers the project note asks for that did not exist — a
beginner overview with three quick starts in `README.md`, and the
manifesto's edited edition as `manifesto.md` at the repository root — and
build `site/`, a React Markdown renderer with Mermaid that publishes the
manifesto, the README, the specification and the skills to GitHub Pages. The
overview states compatibility with spec-driven toolkits rather than
competing with them, and names the package `cairn-protocol` with its `cairn`
binary.

Deliberately not in this unit: one page per release on the site (it renders
the trunk; a release is a tag the site's footer will name once S08 tags);
enabling Pages on the repository, which is the owner's setting; a snapshot
suite for the renderer.

#### Work

```cairn-unit
step: S07
```

- **`manifesto.md`**, the edited edition: the owner's statement in cleaner
  sentences and the same order, 715 words for 699, with a preface that names
  the verbatim original in `docs/cairn/` as the source where the two differ.
  Two phrases were opened rather than changed — "OKF norms" is written out as
  what it means, a knowledge base kept as files with one idea per file and
  every folder navigable from its index; "a shared concept knowledge base:
  protocol, project or coding" is written as the three scopes chapter 6
  states — because an edited edition for a public reader cannot assume the
  owner's abbreviations. The specification's manifesto links point at the
  root edition now.
- **`README.md`**: what Cairn is in one screen — the chronology, the path as
  one folder, the unit, the closure on one exact commit, the checker's
  twenty-four rules and their fixtures, the split between fact and
  judgement, and the sentence on spec-driven toolkits; then three quick
  starts — a new repository with `npx cairn-protocol init`, one coding cycle
  with the three skills, and a repository that already carries the protocol
  with `adopt`, `status` and `update` — a table of where to go next, the
  weight budget, and the licence. 1,163 words.
- **`site/`**: Vite, React, react-markdown with GFM, and Mermaid loaded only
  when a diagram renders. `build-content.mjs` bundles the manifesto, the
  README, `spec/**` and `skills/**` — 74 documents — with the release and the
  commit; the app routes by hash, resolves relative links between bundled
  documents into routes and every other relative link into the repository on
  the forge at the bundled commit, strips frontmatter, and names each page
  from its title. The navigation follows the four layers. Dark mode follows
  the reader's. The build is 607 kB before compression, 186 kB after, and
  the Mermaid chunks load on demand. `.github/workflows/site.yml` builds and
  deploys it to GitHub Pages on every push to the trunk; `SITE_BASE`
  rebases it for a dedicated server.
- **The site is a second implemented area.** `roots.source` gains `site/`
  and the configuration binds it to `docs/modules/site.md`, so a change to
  the renderer is held to the same coherence as a change to the checker. The
  tools stay dependency-free; the site is a reader and has dependencies, and
  its lock file is committed for `npm ci`. `.gitignore` keeps `node_modules`,
  the build and the generated bundle out of the tree.
- Rejected: writing anything for the site that is not already a document.
  The site is a projection of the repository's Markdown; a page written for
  the site alone is the second copy that drifts.
- Rejected: rendering Mermaid at build time. Diagrams are few and the
  library is large; loading it when a diagram appears keeps the first page
  at a fifth of the weight, and the source of every diagram stays a fence in
  a Markdown file the checker's corpus covers.
- Rejected: a snapshot suite for the renderer. A renderer of prose has no
  predicate the prose does not already satisfy; the build is the test, and
  the rendering is judged at the deployed address.
