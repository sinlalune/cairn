# CP-CAIRN-001 — forward plan

Read when planning, never before every step. Each item is one or more work
units; the order is the manifesto's: cut, then shape, then package, then teach.

1. **S01 — the specification on the six stages.** Move `docs/cairn/specification/`
   to `spec/`; write `spec/index.md` on the chronology; fold the current
   normative text into chapter five and cut it; merge the concepts section 4
   lists; keep the borrowed vocabulary. Measure words at the end of the unit.
2. **S02 — the rules.** Retire and demote per the keep and retire lists;
   fold `closure-surface`, `advisory-disposition` and `coherence-audit` into
   `acceptance`; keep every fixture of every kept rule; regenerate catalogue and
   linkage; the retired rules' fixtures go with them.
3. **S03 — one folder per path.** Opening acceptance inline; resume section
   in `index.md`; the lightweight route as specified; `depends_on:` and the
   unblocked view; `foundation` folded, `emergency` dropped. Migrate this
   path's own record to the new shape in the same unit — it is the worked
   example.
4. **S04 — pull request transport.** Default `pull-request` in the config,
   `manual-git` fallback, the drift check as a CI step on the PR; the
   workflow's one required check. This repository's own ruleset already
   matches.
5. **S05 — skills.** Five `SKILL.md` folders; the operations page becomes the
   skills' reference files; cairn-code carries the decision ladder.
6. **S06 — `npx cairn`.** `init` from the thin kit, `status`, `update` by lock
   digest, `adopt` for a repository that carries the protocol without a lock.
   Atomik is the acceptance test for `adopt`.
7. **S07 — README, manifesto edition, site.** Overview, three quick starts,
   the edited manifesto, the React renderer with Mermaid on GitHub Pages.
8. **S08 — budget, pilot, release.** Measure the weight budget onto the
   conformance page, rerun the greenfield pilot from the tagged release, tag
   `1.0.0`, then close.
