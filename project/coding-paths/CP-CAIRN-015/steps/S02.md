# CP-CAIRN-015 S02

### S02 — what `update` and `status` report — **COMPLETE**

#### Plan

Make `status` and `update` build their plan through one function
(ADR-034 decision 4) and read it through one predicate that the pointer
page's list shares, the live view on neither (decision 1, Atomik's third
observation); report the files an update starts managing (decision 3);
stamp every generated page with the release's day and assert two plans
on two days byte-equal (decision 2, Atomik's first); and mark in the
lock the digests that are the host's own bytes (Atomik's second, taken
without a record at the plan review). Carried from S01's review: the
pointer page follows `update --take`.

Definition-of-done item advanced: the second, in full; the seventh's
lock row for the host-baseline mark.

Type `implementation`: four tests failed first — one reading across
`status`, `update` and the page; two plans under a mocked clock on two
days; a host file the kit starts managing; and the declination test's
new lines, the page after `--take`.

Deliberately not in this unit: ADR-034 decisions 5 to 11, which the
register gives to rows 1, 2 and 4 and which this path's scope does not
name; `adopt`'s report (S03); this repository's own lock.

- **`tools/cairn.mjs`**, one plan: `hostPlan(target)` migrates the

  on the view; `updateStatus(target, plan, lock)` plans the pointer page
  from that list and the declined names and reads again; `status` prints
  it, `applyUpdate` applies it, and the reading that lived inside
  `applyUpdate` moved there. A digest of the host's bytes — the lock's
  `hostBaseline`, and the view always, old locks included — reads
  `host`.
- **`tools/cairn.mjs`**, the rest: `releaseDay` — the stamp's
  `stampedAt`, else the source commit's date — stamps `front`;
  `lockFor` writes `hostBaseline` (the plan's, and the view when it
  digests it); `describeStatus` says *to reconcile by hand* and *starts
  managing*; `update` reports *newly managed*; `--take` rewrites the
  pointer page after the file when the page is pristine.

- **`docs/modules/application.md`**, **`spec/reference/repository-layout.md`**:

#### Review

First read: a fresh context, a subagent of this harness, given the
unit's diff and the two criteria; it reproduced its first finding in a
scratch installation and returned in about a minute and a half, on the
first attempt, with nine findings:

- `correctness:` a configuration to reconcile read `host`, and `status`
  printed no line for it while the page and `update` listed it —
  **fixed**, `status` prints a kept host digest that is to reconcile;
  reproduced green with a configuration re-indented to four spaces.
- `correctness:` the configuration's digest is of the host's file as
  migrated and re-serialised, not of its bytes, so a formatting-only
  edit reads as to reconcile — **fixed in the prose**, which now says
  *content, as migrated*; the code is as it was before this unit,
  `update` having written the migrated serialisation since 1.0.
- `correctness:` the `--take` message claimed the pointer page was
  touched on a dry run and when the page was kept, and `--take` of the
  page itself wrote it without its lists — **fixed**, the clause is
  printed only when the page was rewritten, and the follow-up runs for
  the page too, so it lands with its lists.
- `correctness:` `stampedAt` is the day `prepack` ran, so a checkout and
  the tarball of one commit stamp different days — **refused**: ADR-034
  decision 2 names `stampedAt`, and a lock is written by one of the two,
  never both; two plans of one *release* are byte-equal.
- `delete:` the lock's copy of the view under `hostBaseline` is never
  read, since the reading adds the view itself — **refused**: the
  reading adds it for locks written before the field; the lock says so
  because Atomik's second observation asks the lock to.
- `shrink:` `writeLock`'s declined filter repeated `updateStatus`'s —
  **fixed**, the reading returns it.
- `shrink:` `applyAdopt` parsed the configuration `hostPlan` had just
  serialised — **fixed**, the plan carries the migrated configuration as
  its `config`.
- `shrink:` the follow-up to `--take` planned the kit a second time —
  **fixed**, it reuses the plan.
- `yagni:` the release day ran `git` at every import of the module —
  **fixed**, computed on the first page stamped.

Second read, of the fixes' lines alone: a fresh context, a subagent of
this harness, given only those lines and the two criteria; it ran the
suite and returned in about two minutes, on the first attempt, with six
findings:

- `correctness:` after a `--take` across releases the rewritten page
  named the package's release while the lock still named the installed
  one — **fixed**, the page follows a take only at the lock's own
  release; across releases the next `update`, which the command asks
  for, writes it.
- `correctness:` a lock that does not own the page made the follow-up
  throw after the owner's take had landed — **fixed**, the follow-up
  runs only when the lock owns the page.
- `correctness:` `stampedAt` against the commit's day, again —
  **refused**, as above.
- `yagni:` the cached day ignores `planInstall`'s `sourceRoot` argument
  — **refused**: `releaseDay` keeps its root parameter, and the one
  caller of `planInstall` passes the package's own root; the page
  templates never took a root.
- `delete:` the view in the lock's `hostBaseline`, again — **refused**,
  as above.
- `shrink:` `applyAdopt`'s `decide` could be one expression —
  **refused**: lines this unit did not write, and no finding of it.
