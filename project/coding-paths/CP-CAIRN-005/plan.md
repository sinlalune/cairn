# CP-CAIRN-005 — forward plan

Read when planning, never before every step. Each unit implements the
records its surface names and nothing else; every sentence added is
scoped from a record's *What implements this record* table, and the
skills name no record — they say what to do. Each unit runs the review
movement on its own diff, as CP-CAIRN-004's units did, before the unit
skill says so.

1. **S01 — the open skill, the configuration and the binding.**
   `cairn.config.json` gains `transport.registration: manual-git` and the
   binding names it; `cairn-open` step 2 becomes the owner's plan review,
   asked in the chat with the question's shape, the yes written as the
   acceptance; step 3 lands the registration commit on the trunk directly
   and its reference drops the `register/` sequence; step 1 asks which
   area the path writes in and why a whole root, and says the goal opens
   with three plain lines (ADR-001 d1, d2; ADR-010 d2; ADR-019 d3; ADR-021
   d2, d3). Type `implementation`; the gates prove the configuration
   still loads and the fixtures still pass.
2. **S02 — the unit skill, chapter 5 and the work-unit concept.** Five
   movements with the review section and the bounded second read; the
   self-review in five tags; the plan's item, `repair`, no id by hand; the
   failing test first; dependencies before the first gate, the exit code;
   the framework's block moved; the helper agent as the writer; the
   question a unit cannot decide; the concept note and the offered
   session; the API refresh beside the module note. Chapter 5's *Advance
   one work unit at a time* and `spec/concepts/work-unit.md` say the same
   in the specification's voice (ADR-017; ADR-016 d2; ADR-009; ADR-018 d1;
   ADR-008 d7; ADR-007; ADR-020 d2; ADR-021 d3; ADR-022 d3; ADR-023 d4).
3. **S03 — the close skill and the request template.** No closure step;
   the description's order — three lines and the surface link, the
   definition of done item by item, the ledger; the reader's two
   criteria; the try asked in the chat, the merge after the green run as a
   merge commit, the click as the acceptance; the administrative commit's
   content; the README's line; what closing leaves behind; the post-mortem
   read on a red run. The request template opens with the three lines and
   the item-by-item section before `## Candidate` (ADR-008 d1, d3;
   ADR-021 d2, d3; ADR-018 d2; ADR-016 d4; ADR-001 d3–d5; ADR-023 d1;
   ADR-006; ADR-014 d2).
4. **S04 — the stance cut to Cairn's own, and the sixth skill.**
   `cairn-code` keeps deletion turned on the protocol, the test that never
   fires, the three-line step, absorbing the ecosystem, and two lines on
   secrets and errors, and points at Ponytail at the tag ADR-016 names;
   `cairn-learn` is written — what it reads first, the exploration by
   prompting, the learning note and the concept notes, the link from
   outside the wiki — and this repository's bootloader names it beside the
   five (ADR-016 d1, d3; ADR-022 d2).
5. **S05 — the path template and the configuration reference.** The
   goal's three lines, the step's tagged self-review and review section,
   the amendment block; the configuration reference on areas as folders
   and `writes:` as their patterns (ADR-021 d2; ADR-016 d2; ADR-017;
   ADR-002 d2; ADR-019 d1, d3). The register's row 1 names this path.
6. **S06 — the candidate.** Trunk merged in, gates bare, the request
   opened with the three lines first — written by the template this path
   just changed — the definition of done item by item, then the ledger;
   the owner reads the skills before the merge.
