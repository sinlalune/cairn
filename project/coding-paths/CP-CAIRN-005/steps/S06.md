**Fixed — the branch-deletion glob matches another path's branch.** S03
wrote `git branch -r --list 'origin/*cp-example-001*'`, and the line under
it says to delete every name printed that is not `path/cp-example-001`.
In a repository that also runs `CP-EXAMPLE-001-FIX` — a legal id under the
checker's pattern — that prints `path/cp-example-001-fix` and instructs its
deletion: the remote history of a running path, which ADR-006 decision 1
keeps until the path is archived. S03's *first* read checked that the
command ran and printed a stripped name; neither read checked that the
pattern was safe.

`origin/*/cp-example-001` is the fix. It still catches every transport
prefix, `*` crossing `/`, and no longer catches a longer id. It also stops
catching a transport branch that carries the id bare or suffixed; no
transport in this repository makes one, and `cairn-close` step 6 states
the rule the command approximates safely.

**Confirmed, not re-opened — the open reference's unconditional direct
push.** The kit's default is `transport.registration: pull-request`
(`tools/cairn.mjs` line 151, mapped at line 201) and `package.json` ships
`skills/`, so an adopter on the default reads an instruction a protected
trunk refuses and an unprotected trunk obeys, bypassing the request and
its check. The finding is sound, and it is the one this path's record
already lists under *tried and rejected*, from S01's own review: ADR-001
decision 1 — pinned in `governs:` at `c1feab4c` — says "the request
sequence goes; the direct push stays", and the coverage says a record
found wrong is a superseding record by a later path. The fork was written
into this unit, the review named the contradiction, and it was reverted.
The record's entry gains the bot's evidence and its severity; the
disposition does not move.
