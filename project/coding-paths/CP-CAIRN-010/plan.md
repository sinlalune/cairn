# CP-CAIRN-010 — forward plan

Read when planning, never before every step. Each unit runs the review
movement as ADR-017's fourth decision will say from S01 on: a fresh
context where one can be obtained, the writer's own read named as such
where not, the section's first line saying which. Every behaviour change
has its failing test first; `current_step` names the unit whose block is
in the commit.

1. **S01 — the records.** Type `decision`. ADR-017 patched in place with
   decision 4, the fallback and the reader line, dated 2026-09-15 as its
   decision 3 was dated 2026-09-08. ADR-028, the feedback file: the
   channel, when it is written, what a file names, what it is not, the
   owner's words quoted. ADR-029, the checker asks the host nothing:
   supersedes ADR-001 decision 6 and ADR-026 decision 1, the owner's
   ruling of 2026-09-14 and the measured cost; the two superseded
   decisions marked in their records' status lines. The 1.1 page amended
   in place, marked *since 2026-09-15*; the ADR and architecture
   indexes; the register's row carrying this path.
2. **S02 — the skill, the template, the first feedback file.**
   `cairn-unit` movement 4 gains the fallback sentence and the reader
   line; its last movement gains the sentence pointing at `feedbacks/`;
   the path template's review section shows the reader line for both
   reads; `feedbacks/index.md` names the agents' files beside the owner's
   pages; the first agent feedback file, from what path 4's writer
   observed and could not place, four observations with their cost and
   the change to Cairn each asks for.
3. **S03 — the deletion.** `githubSlug`, `forgeGaps`, `readForge`, the
   host half of the profile line and their assertions removed from the
   checker and its tests; the profile line prints the declared transports
   and the enforcement profile; a test proves the checker runs with no
   network; `GITHUB_TOKEN` removed from the checker's step in this
   repository's workflow and in the workflow the kit generates, the
   post-mortem step's token kept; the catalogue, the matrix, the
   soundness note and the conformance page's profile row regenerated;
   `docs/modules/application.md` describes the checker without the
   reading.
4. **S04 — the candidate.** Trunk merged in, gates bare, the request
   opened with the description the audit tool prints; the administrative
   commit on the branch and its check green before the owner is asked;
   the owner reads the first feedback file and the profile line the
   request's run prints before the merge.
