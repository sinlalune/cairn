# CP-CAIRN-010 S03

### S03 — the deletion: the checker asks the host nothing — **COMPLETE**

#### Plan

Make the checker what ADR-029 says it is: a reader of the repository it
stands in, with no network call and no GitHub code, printing a profile
line that claims nothing about the host.

Delete `forgeGaps`, `readForge` and the host half of `profileLine` from
`tools/cairn-check.mjs` with the lines of `main` that read the token and
made the read; move `githubSlug` and `githubRequest` to
`tools/cairn-postmortem.mjs`, the one tool that calls them, with their
tests; rewrite the profile line to the enforcement profile and the two
transports; take `GITHUB_TOKEN` and its twelve-line comment off the
checker's step of this repository's workflow, keep the post-mortem step's
token, invert the workflow test that asserted the token and pin the kit's
generated checker step without one; prove the run makes no network call
with a fixture that makes every network entry point of the runtime throw,
offers a token, and reads the verdict green; and make the conformance
page's profile row, the catalogue, the soundness note and the module note
say what is now true.

Definition-of-done item advanced: the fifth, its checker half — S01
wrote the record. The sixth's clause on the module note is met here too.

Type `implementation`: source, its tests, the module note, the step.
Every behaviour change had its failing test first, and the red run is
in the verification below: four tests failed against the previous code
before the code moved.

**`writes:` widened**, in the record and in the register's row 6, by
`tools/cairn-postmortem.mjs` and `tools/cairn-postmortem.test.mjs`,
because ADR-029 moves the two GitHub functions to the tool that calls
them and the definition of done names `githubSlug` as gone from the
checker; and by `tools/cairn-workflow.test.mjs`, because that test
asserted the token on the checker's step and would have gone red on the
deletion. The post-mortem's token, its step and its output do not
change: the two functions arrive with their comments and the
`user-agent` header names the tool that now sends it.

Deliberately not in this unit: the `comparison` rule's printed messages,
which still say *the forge names none* about GitHub's all-zeros sentinel
— a printed message is a behaviour with a fixture behind it, and ADR-029
decides the reading, not that rule's wording; the catalogue's condition
for the same rule, which is prose the page carries, does say GitHub now.
The post-mortem's own text keeps *the forge* where it means the host it
asks. `spec/concepts/enforcement-profile.md` is outside `writes:` and
still true: host settings need evidence independent of the declaration,
and the evidence is the owner's.
