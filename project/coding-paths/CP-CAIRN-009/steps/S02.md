# CP-CAIRN-009 S02

### S02 — the documentation plane the kit installs, and the concept rules' read — **COMPLETE**

#### Plan

The kit installs the plane 1.1 decided — an inputs folder, a concept
root in three folders, a documentation index that says where a reader
goes, an architecture index, and a module note template that describes
now — and the checker's two concept rules read that root through its
folders instead of flat. It is the least because every file is an index
a record already names and the checker's widening is one read made
recursive in the function that already walks the tree. It does not
touch the pointer page, `update`, the manifest or the chapters.

Definition-of-done items advanced: the third (the plane the kit
installs) and the fourth (the two rules' recursive read).

Type `implementation`: the installer and the checker, their tests and
the adversarial fixture, the `tools/` module note and this step move
together. Both behaviour changes are written as failing assertions
first — the fixture with an orphan inside a folder, and the kit's
planned file set.

**The decision this unit could not make.** ADR-011 decision 2 names the
second concept folder `docs/concepts/<project>` and every record that
carries it — the 1.1 page's table, ADR-011's own, chapter 6's scopes
table — leaves it a placeholder. The kit has no project name: `init`
knows its target, but `update` and `adopt` re-plan from
`cairn.config.json`, which records no name, so anything derived from the
directory drifts the moment it is renamed and `update` writes a second,
empty folder beside the first. Put to the owner in the chat with three
ways to go, tagged by cost. The owner chose the fixed name
**`docs/concepts/product`** — nothing added to the configuration or the
command line, and `update` and `adopt` re-plan identically forever. S05
writes the same name into chapter 6's scopes table.

Deliberately not in this unit: `cairn/README.md`, `update` and `status`
(S03); `REFERENCE_TOOLS`, `cairn-learn`'s manifest entry, Ponytail, the
generated workflow and request template, the lock and the conformance
page's kit line (S04); chapters 3 and 6, `spec/concepts/**` and the
layout reference (S05); this repository's own `docs/architecture/index.md`
and the register's row (S06) — this unit writes only the architecture
index the kit generates for an adopter, which is a different file.

- **`tools/cairn.mjs`** — the plane the kit installs. `docs/inputs/index.md`
  (ADR-011 d1): what existed before the protocol, any format, kept as it
  came, read first by the first ideation session. The single concept root
  index becomes three folder indexes over `CONCEPT_SCOPES` — `cairn`,
  `product`, `learning` — each saying whose vocabulary it holds, and
  `learning` saying a learning note is a concept note with an order
  written by `cairn-learn` (ADR-011 d2, ADR-022 d1); there is no index at
  the root any more. `docs/architecture/index.md`, new: one page per
  feature, interface, contract or **flow**, flow pages here with no folder
  of their own, and the rule that a page naming components states the
  direction of its dependencies in one sentence and carries one Mermaid
  diagram saying the same thing (ADR-019 d2, ADR-023 d2, d3).
  `documentationIndex` replaces the one-paragraph `folderIndex` call: a
  table of where each kind of page lives, and the section on the page a
  newcomer reads first — one worked example before any explanation, the
  concept notes as its glossary, the architecture page that governs it,
  and the API's own documentation where the surface is an API, which
  Cairn names and installs nowhere (ADR-012, ADR-023 d3, d4). The concept
  links are computed from the bound root, because a host may bind its
  wiki outside the documentation plane — this repository does — and a
  hard-coded `./concepts/` would point at nothing.
- **The module note template** gains ADR-010 d1 in the template itself:
  the note describes the area as it is now, a unit rewrites the sentences
  that stopped being true and adds none about itself, and what a path did
  belongs to the journal.
- **`tools/cairn-check.mjs`** — the two concept rules read the root
  through its folders. `corpusFindings` walks the root with the `walk`
  the corpus loader already uses and names each note by its path under it;
  `orphanConcepts` and `addedConcepts` treat any `*/index.md` as an index;
  `concept-growth`'s previous state is read with `ls-tree -r` and mapped
  to the same relative paths, so a note added in any folder is reported.
- **`conceptLinkTargets`**, new and exported, resolves a link to the note
  it reaches. It exists because widening the capture to admit folders
  broke the rule in the worst possible way and nothing pure was there to
  catch it — see the self-review below.
- **`tools/cairn-rules.mjs`** and **`spec/reference/conformance.md`**: the
  two rules' trigger and enforcing text say the root is read recursively
  and a note is named by its path; the hand-written matrix row above the
  generated markers says the same, and notes that the protocol's own root
  is flat and is the `cairn` scope itself. The page was regenerated with
  `npm run cairn-rules -- --write`.
- **Tests, each written first and seen red**: the fixture with an orphan
  inside `docs/concepts/learning/`; the two predicates against folder
  paths and folder indexes; `conceptLinkTargets` against the four ways a
  link is written; and the kit's whole installed plane, including a
  non-default `roots.concepts`.
- **`docs/modules/application.md`**, the `tools/` area's note: what the
  kit installs now, and how the two concept rules read.

**One widening of `writes:`.** `tools/cairn-rules.mjs` is added to the
record. `spec/reference/conformance.md` is already declared, but its two

ADR-011 d2 decided unless its generator does, and hand-editing between
the markers would be undone by the next `cairn-rules --write`. S06
carries the same widening into the register's row 4, as the plan says.

**A number removed rather than moved.** The kit's installed set grew, and
`cairn.test.mjs` asserted `files.size + 1 < 30`. ADR-022 d2 superseded
ADR-013's cap: what the kit installs is measured and reported, never a
target. The assertion is deleted rather than raised, the test renamed,
and the header comment's *under thirty files* replaced by the statement
that the count is measured. The module note reports today's measurement —
31 files and the lock on `ci`, 30 on `local` — and bounds nothing.

#### Self-review

- `correctness:` widening the link capture to admit folders —
  `((?:[a-z0-9-]+\/)*[a-z0-9-]+\.md)` — broke `concept-orphan` on this
  repository: `../concepts/worktree.md` holds `./` at offset one, that
  earlier match now succeeds because the capture admits a slash, and it
  swallows `concepts/`. Every one of the 71 concepts read as unlinked and
  the gate reported 50 orphans. Caught by running this repository's own
  checker, not by any test. Fixed by taking the note after the LAST
  `concepts/`, and the resolution extracted into the pure
  `conceptLinkTargets` with the four link shapes asserted — because the
  inverse of this bug is silent: swallow the other way and every concept
  reads as linked, `concept-orphan` fires on nothing, and the fixture
  still passes.
- `delete:` the documentation index's *Where the words are* section — it
  restated the table's three concept rows and the orphan sentence each
  folder index already carries. Cut.
- `shrink:` the architecture index closing with *what was decided is
  under the decision records; what a path did is in the journal* — a
  folder index pointing away from its own folder, and the documentation
  index's table says it. Cut to the clause that is about this folder.
- `yagni:` `CONCEPT_SCOPES` was exported and nothing outside the file
  reads it; the kit test names the three folders literally, which is the
  assertion that would catch a scope quietly renamed. Un-exported.
- `delete:` the kit's `files.size + 1 < 30` assertion, deleted rather
  than raised — ADR-022 d2 makes the count a measurement, and a number
  moved is a number still being defended.
- `stdlib:` the recursive read reuses `walk`, the function `markdownCorpus`
  already walks the tree with; no second traversal was written.
- Widening of `writes:` named above: `tools/cairn-rules.mjs`, because the
  conformance rows are generated from it.
- Net across the nine files, before this step record: 266 added, 38
  removed — of which the installer is +131/−18 and the checker +38/−9.

#### Review

First read, a fresh context given this unit's diff and the two criteria,
the ladder and correctness, and nothing else. Eleven findings; each with
its disposition:

- `correctness:` `conceptLinkTargets` admitting **any** `./a/b.md` once
  the capture took folders, so `./modules/application.md` entered the
  linked set and a stray `./product/fixture.md` in an unrelated document
  would clear that note of orphanhood — **fixed**, and it is the same
  widening that caused the near-miss below, in its quiet direction.
  Through `concepts/` the folders are the note's own; reached by a bare
  `./` they are some other document's, so a multi-segment target that
  never went through `concepts/` is dropped. The case the reader named is
  now asserted.
- `correctness:` `spec/reference/conformance.md`'s installation row still
  reading *the five skills … 26 files*, while this same diff rewrote the
  module note to 31 — **fixed**. S01 deferred this line to S04 because
  the manifest was not final; that reasoning stops holding the moment one
  diff makes the two pages contradict each other. The row now names six
  skills and reports the measurement with the sentence that it is not a
  target. S04 updates the figure when it changes the manifest, as any
  unit that moves a measurement updates its report.
- `correctness:` `assert.doesNotMatch(note, /history|changelog/i)`
  passing whether or not the change exists, because neither word was in

- `correctness:` `assert.match(docs, /API/)` checking that three letters

- `correctness:` `/protocol/i` not distinguishing the `cairn` index from
  its neighbours, since the `learning` purpose also contains *a protocol*
