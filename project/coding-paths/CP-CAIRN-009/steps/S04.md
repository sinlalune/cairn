# CP-CAIRN-009 S04

### S04 — the manifest, the generated adapter and template — **COMPLETE**

#### Plan

The kit ships the tool 1.1 added and generates the two host files paths
3 and 5 already fixed here, so an adopter's first CI run and first
request look like this repository's. It is the least because every file
is one the kit already copies or already writes, and the shapes are
taken from this repository's own rather than invented. It does not touch
the checker, the chapters or the concepts.

Definition-of-done items advanced: the seventh (the manifest, Ponytail,
the two removal candidates, the lock and the count) and the eighth (the
generated workflow and request template).

Type `implementation`: the installer, its tests, the `tools/` module
note and this step move together. Every behaviour change is written as a
failing assertion first.

**The two candidates ADR-013 named for removal, decided on value.** Both
are **kept**, each for its own reason and neither for a number, as
ADR-022 d2 requires.

- `tools/cairn-config.schema.json` — read by no tool: `cairn-config.mjs`
  validates independently and never opens it. It is therefore exactly
  what ADR-013 called it, an editor aid the loader does not need — and
  that is the argument for keeping it. `$schema` is the standard pointer
  an editor honours, and the configuration is the one file an adopter
  hand-edits. Removing it means either a dangling `$schema` or dropping
  that too, trading a working aid for nothing but one fewer file.
- `project/index.md` — the manifesto's engine section commits to a tree
  where *every folder is navigable from its index*. `project/` is one of
  the two planes. Removing its index to save a paragraph contradicts a
  commitment the protocol makes about itself.

Deliberately not in this unit: chapters 3 and 6, `spec/concepts/**` and
the layout reference (S05); this repository's `docs/architecture/index.md`
and the register's row (S06). This repository's own `.github/**` is
excluded by the path's acceptance and is path 3's — this unit reads it as
the shape the generated files must match, and changes none of it.

#### Self-review

- `delete:` the kit's workflow was about to gain a `cairn-test` step by
  copying this repository's own wholesale. It has no suite to run, so the
  step would have failed on an adopter's first push. Cut before it was
  written, and the absence is now asserted rather than assumed.
- `shrink:` the generated workflow's comment on the fork case — *this
  repository has one owner and no fork requests, and the case is named
  here rather than handled* — is true of this repository and says nothing
  to an adopter, who may well take fork requests. Cut to the fact: on a
  fork the token is read-only and the comment step ends in a 403.
- `stdlib:` no diff, no YAML writer, no dependency resolver was written.
  The dependency is two strings in a constant; the workflow is text.
- `yagni:` `DEPENDENCIES` is a map rather than a single string, which is
  one entry more general than today needs — kept, because the lock field
  and the page section both iterate it, and a second dependency would
  otherwise be a schema change in two files instead of one line here.
- Considered and kept: the equality test lists shared lines rather than
  asserting the two files are identical. They are not meant to be
  identical — one runs a suite the other has not got — and an assertion
  of identity would have to be deleted the first time they legitimately
  diverge, which is how a test stops being read.
- The two removal candidates are kept and the reasons are in the plan
  section above, each about what the file is worth. Neither mentions a
  count, which is what ADR-022 d2 asks.
- No widening of `writes:`; every file here was already declared. This
  repository's own `.github/**` was read and not touched.
- Net across the four files, before this step record: 218 added, 17
  removed — of which the installer is +85/−10.

#### Review

**How this read was made.** Two fresh contexts were given this unit's
diff and the two criteria; both hung, at ten and twelve minutes, each
having emitted the single line *"I'll start by reading the diff"*. That
is ten of fourteen review contexts across S01 to S04. The read below was
made by this same context, as S03's was, and is recorded as such rather
than implied. The owner has ruled that the movement's missing fallback
gets a record in its own path; until it exists, this is what a writer can
honestly do.

What the reader could not have done, and was done instead: the generated
workflow was **parsed as YAML** and every claim its comments make was
checked against the parse — the push trigger resolves to `[main]`, the
job carries exactly `contents: read`, `actions: read`,
`pull-requests: write`, the four steps are in order, and the post-mortem's
condition is `failure() && steps.cairn-check.conclusion == 'failure'`.
Every `${{ }}` expression survived the template literal intact and no
escaped backtick leaked into a comment.

Findings, each with its disposition:

- `correctness:` the generated workflow set `GITHUB_TOKEN` on the
  **checker** step. I put it there by copying this repository's own, and
  no record this unit implements asks for it: ADR-005 is the trigger,
  ADR-014 d1 is the post-mortem step. The token on that step exists for
  one thing, the forge reading ADR-026 d1 restored — and the owner ruled
  on 2026-09-14 that `cairn-check` asks the host nothing, a ruling that
  supersedes ADR-026 d1 and is waiting for its own path. Writing it into
  every adopter's workflow now would grant a permission for a reading
  already ruled out, and leave that path a line to walk back in the kit
  as well as here. **Fixed** — removed from the checker step. It stays on
  the post-mortem step, where ADR-014 d1 needs it for the red-run reading
  and the one comment, and where no ruling touches it.
- `correctness:` an old `cairn.lock.json` has no `dependencies` field —
  checked, and nothing reads it: `installationStatus` uses `manifest` and
  `host` only, so a 1.0 lock migrates without special handling.
- `correctness:` `cairn-postmortem.mjs` imports its predicates from
  `cairn-check.mjs`, which is in `REFERENCE_TOOLS`, so the tool the kit
  now copies has its dependency copied with it.
- `shrink:` the fork sentence in the generated workflow said *this
  repository has one owner and no fork requests*, which is true here and
  false for an adopter — **fixed** in the self-review above, before this
  read, and noted again because the generated text is the thing an
  adopter keeps.
