Findings, each with its disposition:

  `docs/concepts/{cairn,<product>,learning}/`. Angle brackets mark a
  repeatable name in that tree, so the row offered the folder as the
  adopter's to name — which is what every record said before the owner
  fixed it, and what chapter 6 two files away now contradicts by naming
  `product/` outright. **Fixed**: the literal name, and the row gains
  *and none at the root*, which is the other half of ADR-011 d2 and was
  missing.
- `correctness:` chapter 6's scopes table says the protocol scope lives
  in `cairn/` under the concept root while the paragraph below says
  `spec/concepts/` **is** the protocol scope — checked, and it is the
  distinction ADR-011 d2 draws, not a contradiction: the folder is where
  an adopter writes about Cairn's words, the wiki is where Cairn's own
  are defined. The paragraph exists to stop a reader taking the row for
  the whole story, so both stay.
- `correctness:` chapter 3 says the README carries a line per surface
  without saying who owns it — checked against ADR-023 d1, which says the
  kit installs no README and owns none. Chapter 3 never claims it does,
  and the layout table's README row already says whose it is. No change.

  they will find on disk, and the row above it in the table names them
