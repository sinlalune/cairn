# CP-CAIRN-009 S08

### S08 — six chapters, six destinations — **COMPLETE**

#### Plan

The pointer page's six chapter links go to six chapters instead of six
times to the top of one page. It is the least because the chapters are
six headings of one file and the fix is the anchor each already has. It
does not change what the page says or anything else the kit writes.

Definition-of-done item advanced: the fifth — `cairn/README.md` with the
six chapters linked at that commit, which was not met.

Type `implementation`: the generator, its test, the module note and this
step. The behaviour changes, so the assertion was written and seen red
first.

**Why there is an S08 at all.** The owner ran `cairn init` into an empty
folder before the merge, as ADR-001 d3 requires, and read what it wrote.
The pointer page listed six chapters over one URL: *1. Idea and ideation*
and *6. Learning loop* both landed at the top of `spec/index.md`. ADR-013
d1 asks for the six chapters, **each one link**. The labels and the
one-line descriptions were right and the destinations were not, which is
a defect no test caught because no test compared the six targets with
each other — `outwardLinks` proves a link resolves, and six identical
links all resolve.

The candidate `5bd3afa` is void by the rule that a candidate is an
identity rather than whatever is at `HEAD` later, and the path returned
to `running` in `98eaa4d` before this unit.

- **`tools/cairn.mjs`**: `anchorOf(title)` slugs a chapter title as the
  forge slugs a heading — lowercased, punctuation dropped, spaces
  hyphenated — and `pointerPage` links each chapter at

- **`tools/cairn.test.mjs`**: the six chapter lines are parsed out of the
  generated page; six lines, six **distinct** targets, and each anchor
  checked against the set of `##` headings `spec/index.md` actually
  carries, slugged the same way. Written before the fix and seen red.
- **`docs/modules/application.md`**: one clause, that the chapters are six
  headings of one page and each is linked at its own anchor.

**What the defect was, exactly.** Six labels over one URL. Every chapter
link was `…/spec/index.md`, so the page offered six destinations and had
one. `outwardLinks`, the guard that proves every link the kit writes
resolves, passed — because six identical links all resolve. The defect
was in a dimension nothing compared: the targets against each other.

#### Self-review

- `correctness:` the first test asserted only that the six anchors were
  **distinct** and each began with its own digit. Six distinct anchors
  that land nowhere are six broken links, so that assertion would have
  passed a fix that was still wrong. Replaced by checking each anchor
  against the set of headings `spec/index.md` really carries, and both
  directions were proved by mutation: identical links fail it, and an
  anchor pointing at no heading fails it.
- `native:` `anchorOf` derives the slug from the title instead of a
  seventh column in `SPEC_CHAPTERS` holding it by hand. A hand-written
  anchor beside a title is two things to keep in step, and the one that
  drifts is silent.
- `shrink:` the comment on `SPEC_CHAPTERS` explains why an anchor is
  needed at all — because the six are headings of one page — which the
  reader cannot get from the code. It does not restate what `anchorOf`
  does; the line below says that.
- `delete:` nothing. The change is one function and one argument.
- Considered and not done: applying `anchorOf` to the skills list too.
  The six skills are six separate files and already have six
  destinations; there is nothing to disambiguate.
- Net: 13 added, 2 removed in the installer; 14 added, 1 removed in its
  test; 3 added, 1 removed in the module note.
