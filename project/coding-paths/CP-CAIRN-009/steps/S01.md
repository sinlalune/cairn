# CP-CAIRN-009 S01

### S01 — what `init` writes, and the bootloader — **COMPLETE**

#### Plan

`cairn init` declares `transport.registration: manual-git` whatever
`--transport` is given, and the bootloader it writes carries the two
lines of 1.1 that reach every session and names the sixth skill. It is
the least because both are text the installer already generates — one
field, one option's meaning, one binding row, two rules and one list
item — and no rule, file or command is added. It does not touch the
manifest, the documentation plane the kit installs or the pointer page.

Definition-of-done items advanced: the first (ADR-024) and the second
(ADR-021 d1, ADR-011 d3, ADR-022 d2, ADR-014 d2).

Type `implementation`: the installer, its tests, the module note of the
`tools/` area and this step move together. The behaviour changes, so
every assertion is written and seen red before the generator moves.

Deliberately not in this unit: `planInstall`'s manifest, `cairn-learn`'s
entry, `REFERENCE_TOOLS` and the lock (S04); the inputs folder, the
three concept folders and the indexes (S02); the pointer page, `update`
and `status` (S03); chapters 3 and 6, the concepts and the layout (S05);
this repository's architecture index and the register's row (S06). The
module note is refreshed here for what this unit changes; S06 reads the
whole note against the candidate.

**One reading stated.** The second item of the definition of done asks
that the bootloader the kit writes say `npm test` is an alias of
`cairn-test`. ADR-014 decision 2, which governs it at its pinned blob,
says the opposite of the kit: *the kit installs no suite and its workflow
runs no test step, as today; the adopter's `npm test` is the adopter's,
and neither the kit's `package.json` nor its workflow names it*, and its
implementation table names `package.json`, `.github/workflows/cairn.yml`
and `AGENTS.md` — this repository's three, the first two named as this
repository's in the same sentence. The kit writes no `cairn-test`
script, so a generated bootloader claiming the alias would be false in
every installation. The alias sentence is therefore in this repository's
`AGENTS.md`, and the kit's bootloader names no suite at all; a test
asserts both halves. The owner sees the generated file at the try before
the merge.
