# CP-CAIRN-009 S09

#### Plan

`update --take` refuses a file this installation never received, the
to-reconcile list stops evaporating, and the notice an adopter with their
own `package.json` reads names every script the kit would have written.
It is the least because each is one condition read from the right source:
the lock instead of the plan, the file on disk instead of the lock, and
the generated manifest instead of a sentence repeating it. It does not
change what any of the three commands is for.

the seventh (the manifest and the scripts the kit writes).

step. Each behaviour change was written as a failing assertion first, and

#### Work

- **`takeRelease` reads the lock, not the plan** — the destructive one.
  The plan says what the release *would* install; the lock says what this
  repository actually received. `init` drops `package.json` when the
  adopter already has one, so the plan carries it and the lock does not,
  and `plan.files.has(path)` therefore let `--take package.json`
  overwrite a real product manifest — name, version, build and test
  scripts, dependencies — with the kit's four-line template, while
  printing *discarding what was edited here; nothing else was touched*.
  It had never been edited and was never installed. Now a path absent
  from `lock.manifest` is refused by name, with the sentence that a file
  the kit skipped at `init` stays the adopter's.
- **`reconcile` compares the file with the template**, not the template
  with the lock. `writeLock` records what the kit *would* have written —
  deliberately, so `status` can still see an edit — so a second update at
  the same release found template and lock equal, dropped the file, and
  left the pointer page saying *Nothing* over an edit nobody had settled.
  The page's own promise is that the list stands until an update finds it
  empty. Unreconciled is now a fact about now: the file on disk differs
  from the template. It cannot evaporate, and it clears when the file is
  taken or matches.
- **The scripts notice is read off the generated manifest.** It named
  three scripts by hand and S04 added a fourth, so an adopter with their
  own `package.json` received `cairn-postmortem.mjs` and was never told
  the command. The notice now iterates the manifest the kit would have
  written, which is why the deletion moved one line down — the file is
  read before it is dropped from the plan.
- **`docs/modules/application.md`**: what `--take` refuses and what the
  reconcile list means.
