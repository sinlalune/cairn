# CP-CAIRN-008 S09

### S09 — the gate reads the integration it judges — **COMPLETE**

#### Plan

Give the changed-file rules a comparison that spans an arrival, and make the
checker say so when it has none.

Item 13. Two halves: the workflow supplies a base that predates what it judges,
and the checker refuses to report OK over a comparison that cannot distinguish
anything — because a workflow is an adopter's to edit, and a gate that trusts
its own input is how this defect survived.

It does not change any rule's judgement; it changes what they are given. It
does not touch the `transition` parent reading, which is S10.

Definition-of-done item advanced: the thirteenth.

Type `implementation`: the checker, the catalogue, three test files, the
workflow, the kit and its test, the conformance page, the soundness note, the
module note, and this step. Every behaviour change has its failing test first.

Deliberately not in this unit: `integrationState` and the `manual-git` fixture
(S10, which must land with this one); the `transition` reading itself, decided
by ADR-027 and not implemented here.

**Widening of `writes:`**: `tools/cairn.test.mjs`, added in this unit. The kit's
generated workflow carries the same base line, and an assertion that it does is
the only thing that keeps the adopter's copy from drifting back; the
registration widened by `tools/cairn.mjs` and not by the file that tests it.

- **One new blocking rule, `comparison`**, standing behind *One invocation, one
  verdict: local and CI agree on one tree* — a stated requirement that carried
  fixtures and no predicate, and that this defect violated exactly. It reports
  two shapes, both `inconclusive`:
  - a base that **does not resolve**. `resolveBase` took `--base` on trust and
    handed it to `git merge-base`, which throws; the process died with a Node
    stack trace and no finding. CI supplies that flag from the forge's event,
    whose value on a branch's first push is forty zeros, so an adopter met it
    on their first push to their trunk.
  - a base that **resolves to the commit under judgement**, off a path branch.
    That is the shape the old workflow produced on every push to the trunk.
- **`.github/workflows/cairn.yml`** and **the workflow the kit generates**: the
  base is the target branch on a request and `github.event.before` on a push.
- **`tools/cairn-workflow.test.mjs`**: the assertion that pinned
  `origin/${{ github.base_ref || 'main' }}` is replaced by two that require a
  base per event, and one that refuses the blind fallback's return.
- **`tools/cairn.test.mjs`**: the same, asserted on a really installed kit.
- **`tools/cairn-fixture.test.mjs`**: two adversarial cases — the unresolvable
  base, and an arrival judged against itself, which asserts both that a
  spanning base judges it and that the deployed shape is reported rather than
  green.
- **`tools/cairn-rules.mjs`**, **`tools/cairn-rules.test.mjs`**, the catalogue,
  the conformance page, `tools/soundness.md`, `docs/modules/application.md`.

#### Review

First read, a fresh context given this unit's diff and the two criteria. It
reverted the three source files in a scratch copy, re-ran the suite there, and
built throwaway kit repositories to probe the predicate. Ten findings:

- `correctness:` **the kit's workflow also triggers on `push: branches:
  [<trunk>, "path/**"]`, and the new base broke path-branch pushes for every
  adopter.** On a path push `base_ref` is empty, so the base fell through to
  `github.event.before` — the branch's own previous tip, which is the
  `--previous` form `comparisonRef`'s comment condemns as how twenty-six edited
  records went unjudged. Measured in a fresh kit repo: two changed files became
  one. Invisible here, whose workflow triggers on the trunk alone — **fixed**:
  the base is the trunk unless the pushed ref IS the trunk.
- `correctness:` an adopter's first push of any path branch went red, the zeros
  sentinel being blocking — **fixed** with the above, and the sentinel is now
  advisory in its own right: the forge saying *nothing precedes this* is a fact
  about the history, not a broken input, and failing a repository's first push
  would refuse a state the writer cannot avoid.
- `correctness:` `baseIsHead` tested IDENTITY where it needed `merge-base`. A
  base that is a DESCENDANT of HEAD gives the same empty comparison and went
  green; a force-push rewinding the trunk sends exactly that — **fixed**, the
  test is `merge-base(base, HEAD) === HEAD`, with a fixture that rewinds a
  trunk.
- `correctness:` *never crashes on an unresolvable base* was half true.
  `refExists` answers "is this a commit", never "can it be compared with mine",
  and a base on an unrelated history still died inside `git merge-base` with no
  verdict — **fixed**, the guard runs before `changedFiles`, verified against a
  real orphan history.
- `correctness:` the rule fired on the no-flag fallback `resolveBase`'s own
  surviving comment says is tolerated on purpose, with a message telling the
  reader to pass a `--base` they had not passed — **fixed**, it asks only where
  a base was requested.
- `correctness:` the catalogue documented one of the rule's two shapes, on the
  page requirement 4 designates as the enforcement authority — **fixed**.
- `correctness:` four documents in this path's `writes:` still asserted the
  defect in the present tense, which item 13 forbids by name — **fixed**, and
  two more the second read found.
- `correctness:` the `spanning` half of the arrival fixture asserted only that
  *something* blocked, which passes on the reverted source — **fixed**: it
  names `acceptance`, and asserts that rule does NOT fire in the blind shape,
  which is what makes the report necessary.
- `correctness:` both messages said every changed-file rule was *SKIPPED*; they
  are narrowed to the working tree, which in CI is clean and locally is not —
  **fixed**.
- `correctness:` the index's unit list stopped at S07 — **fixed**, S08 and S09
  added.
