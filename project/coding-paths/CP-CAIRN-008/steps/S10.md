# CP-CAIRN-008 S10

### S10 — the ready on any parent — **COMPLETE**

#### Plan

Make `transition` read the `ready` behind an arrival where it actually sits.

[ADR-027](../../../../docs/adr/ADR-027-the-ready-behind-an-integrating-commit.md)
decides it: any parent of the integrating commit. `integrationState` read
`commit^`, the first, which is a `pull-request` shape; on `manual-git` the
`--no-ff` merge IS the integrating unit, its first parent is the trunk at
`running`, and the branch's `ready` sits on its second.

It is the least because it is one expression over the parent list the function
already computes, and no transport branch. It does not change what ADR-001
decision 7 forbids, and it does not touch the base — S09's.

Definition-of-done item advanced: the fourteenth, completing it.

Type `implementation`: the rule, three fixtures, the catalogue, the conformance
row, the soundness note, the close skill and its reference, the module note,
and this step. The behaviour change has its failing test first.

Deliberately not in this unit: anything about the comparison itself, which S09
settled and which this rule depends on — without it this change would be
unobservable.
