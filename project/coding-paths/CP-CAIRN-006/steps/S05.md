# CP-CAIRN-006 S05

### S05 — what a range means — **COMPLETE**

#### Plan

ADR-004 decision 3 with repairs 005 and 006 of decision 6. One subject:
on a host that forbids rewriting, the only way to a current base is to
merge the trunk in, so the range from the base to the candidate always
carries other paths' completed units — and every rule that walks it must
read only this path's own records as evidence about this path.

**Decision 3, and the audit it asks for.** The three range walkers are
read against that sentence. Two of them — `record-integrity` and
`record-date` — walk the comparison ref, which is the merge-base with
the trunk: the merge-base advances with every trunk merge, so a record
that arrived through one is behind the comparison and was never in the
range. That is a property of `comparisonRef`, not of the two rules, and
it is proved here rather than asserted. The third, `provisional`, walks
`base_commit..subject_commit` — a PINNED range, which is the one shape
the merge-base cannot correct: every trunk commit merged since
registration is inside it. It reads this path's own commits alone.

**Repair 006, what resolves a provisional commit.** The 1.0 rule is a
timeless grep — the trailer anywhere in the range — where the unit
reference describes it chronologically: *the completed unit's own commit
supersedes it*. A provisional commit is resolved by a LATER commit of
the same path that publishes a valid completed unit, and by nothing
else. The adopter's first repair counted a step record under any `CP-*`
folder, so another path's units, merged in from the trunk, cleared this
path's draft.

**Repair 005, a supersession that is read.** A pushed step record that
was edited cannot be un-edited on a no-rewrite host, and the remedy the
specification states — *add a superseding record naming both ids* — has
had no predicate: the conformance page carries it as a gap. A later step
record of the same path may bind the mutation by naming the blob it
replaces and the blob it adds, and `record-integrity` reads the claim
against the record's real blobs: bound, the mutation is stated as an
advisory instead of refused; named wrongly, the refusal says so.

Definition-of-done item advanced: the sixth.

Type `implementation`: behaviour changes, so the failing tests come
first.

Deliberately not in this unit: decision 4's fixture sweep over every
blocking rule (S07) — this unit writes the two helpers that sweep needs
and uses them where its own subject requires a trunk merge. The writer's

`cairn-unit` skill tell a writer to declare one — is row 1's surface and
excluded by item 10; the shape is stated on the conformance page and

- **`provisional` reads this path's own commits.**
  `unresolvedProvisionalCommits(path, trunkRef)` walks
  `base_commit..subject_commit --not <trunk>`: what a trunk merge brought in
  is reachable from the trunk, and what remains is this branch's, which under
  one writer per branch is this path's. With no readable trunk there is no
  scoping, and the run says it could not decide rather than deciding the
  broader question.
- **A draft is resolved by the unit that finished it.**
  `unitCompletionCommits` finds the commits of this range that publish a
  `cairn-unit` block — valid by the same reading `work-unit` uses — for a step
  the record did not carry at that commit's parent, under this path's own
  folder or its flat record and nowhere else. `unresolvedProvisional` keeps
  the drafts no later commit answers; a draft does not answer itself, and a
  merge commit lists no files, so merging the trunk in finishes nothing.
- **A mutated step is answered by a later step that binds both blobs.**
  `parseSupersession` reads `supersedes: <file>@<blob it replaces>..<blob it
  adds>` from a step's own block — the repository's `governs:` idiom with
  Git's range punctuation — and `supersessionBinds` decides, in `evaluate`,
  whether the claim names the blobs the record really has: the blob that added
  it, followed through relocations, and the blob it carries now. Bound, the
  mutation is stated as an advisory; named wrongly, the refusal prints the two
  ids the record does carry.
- **The audit decision 3 asks for.** `record-integrity` and `record-date` walk
  the merge-base with the trunk, which advances with every merge, so a record
  that arrived through one is behind the range. Read and left alone, with a
  fixture that lands another path's unit on the trunk, edits it there, merges
  it in, and requires this run to report neither — while still reporting this
  path's own misdated record in the same breath.
- **Four fixtures and the two helpers S07 needs**: another path's completed
  unit landed on the trunk through its own `--no-ff` merge and merged in here;
  a draft of this path finished by a later unit; another path's draft carried
  in by that merge; and an edited step answered by a bound supersession, with
  the claim that names the wrong blob refused first.
- **The conformance page states the sentence once**, the two rows say what
  they read now, the soundness note carries the proxy this rule was, and the
  module note says what the checker reads about a range.

#### Review

First read, a fresh context given this unit's diff and the two criteria, and
nothing else. Ten findings; each with its disposition:

- `correctness:` the supersession exemption was not restricted to a later step
  of the same path, which is what every message and page in the diff said it
  was. `pathWorkUnits` reads the mutable `index.md` beside the steps, and the
  reader proved it: a `cairn-unit` block appended there, with no step record at
  all, **dropped `record-integrity` from blocking to advisory on a committed
  edit to a pushed step** — a claim that can be added to clear the gate and
  deleted the next minute — **fixed**: a claim is readable only from an
  append-only step record, with the mutable-record case as a fixture.
- `correctness:` the superseded file was unconstrained, so one path's step
  could legitimize an edit to another path's record — the very sentence ADR-004
  decision 3 states, broken by the rule added beside it — **fixed**: the
  record named must sit in the declaring step's own folder.
- `correctness:` nothing required the declaring unit to be a valid one, where
  the provisional half explicitly requires `workUnitErrors(unit).length === 0`
  — **fixed**, the same reading on both sides.
- `correctness:` *later* appeared in four comments and no predicate —
  **refused, and the comments corrected instead**: a claim names the blob the
  record carries AFTER the edit, so no step written before that edit can name a
  text that did not exist. The binding is the ordering, and the predicate I
  first added for it was two `git log --follow` calls no repository could make
  fire. The reasoning is in the code, where the next reader meets it.
- `correctness:` an unreadable `git log` in `unitCompletionCommits` returned
  "no completions", which REFUSES the candidate, while its sibling failure —
  an unresolvable trunk — is deliberately inconclusive — **fixed**, it returns
  `null` and the run says it could not decide.
- `correctness:` the decision-3 fixture exercised none of the changed code; the
  reader restored the old checker and showed it passes verbatim — **fixed by
  saying what it is and adding the half that bears on the sentence**: it is the
  guard on a property that was already true, and it now also pins the base
  BEHIND the merge and requires the same run to read the other path's record
