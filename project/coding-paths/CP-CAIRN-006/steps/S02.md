# CP-CAIRN-006 S02

### S02 — the profile line and the transition — **COMPLETE**

#### Plan

Two decisions of ADR-001, one unit.

**Decision 6, the profile line.** Every run prints, beside the profile,
the transports the configuration declares and what the forge does not
enforce on this repository. The record decides how it is known: with a
forge token the checker reads the trunk's rules and the repository's
merge settings; without one it prints that the forge was not read. The
line is output, never a finding, on `ci` and `local` alike, and no
failure of the read changes an exit code.

**Decision 7, the transition.** `transitionErrors` loses its
`trunkIntegration` escape, so a trunk commit taking a path from
`running` to `done` with no `ready` commit behind it is refused, and the
refusal names the remedy (ADR-008 decision 6): declare `ready` on the
branch first, in the administrative commit that carries
`subject_commit`. The fixture is the shape path 1's own closing took,
and it carries a merged trunk commit of another path's unit (ADR-004
decision 4).

Definition-of-done items advanced: the second and the third.

Type `implementation`: behaviour changes, so the failing tests come
first (ADR-018 decision 1) — the transition's unit test and its
adversarial fixture, and the unit tests of the profile line's pure
halves.

Deliberately not in this unit: the seal at every transition and
`writes-overlap` (S03); ADR-004's six corrections (S04); one commit for
one path and the journal key (S05); the `review` rule, the fixture
sweep, the catalogue regeneration and the soundness lines (S06). The
concept article `enforcement-profile`, which ADR-001 decision 6 also
names, is outside this path's `writes:` and outside row 2 of the
register; it is not touched and is named in *Tried and rejected*.

- **The transition loses its escape.** `transitionErrors` had
  `trunkIntegration`, which exempted `running → done` off a path branch from
  the table. It is gone, so the edge is refused by the table itself, and the
  message names the remedy: declare `ready` on the branch first, in the
  administrative commit that carries `subject_commit`. Nothing else in the
  table moves — `ready → done` was already allowed, and `onPathBranch` still
  selects the path-branch message.
- **The fixture is path 1's own closing shape**: on the trunk, a record taken
  from `running` to `done` with no `ready` behind it. Its history carries a
  merged unit of a second path, as ADR-004 decision 4 asks. Proved adversarial
  by restoring the escape: the fixture then reports only `journal-entry`.
- **The profile line.** A third header line, and a `profile` object under
  `--json`: the transports the configuration declares, and what the forge does
  not enforce. `githubSlug` finds a GitHub remote or answers `null`;
  `readForge` asks the trunk's rules and each ruleset behind them;
  `forgeGaps` names the three things ADR-001 decision 6 names; `profileLine`
  renders. Every read answers and none throws, so the line cannot reach an
  exit code; `main()` is now `async` and its rejection handler exits 1 rather
  than exiting 0 with no verdict.
- **What the forge does not enforce is read from the rules that apply to the
  trunk.** ADR-001 decision 6 says "the trunk's rulesets and the repository's
  merge settings"; on GitHub the setting that governs what lands on the trunk
  is the ruleset's `allowed_merge_methods`, and the repository's own
  `allow_squash_merge` is not it. Read against the live API, this repository
  prints exactly the honest line the record wrote by hand on 2026-09-06: the
  check is required on the exact commit, only merge commits land, and one
  actor bypasses the trunk's rules.
- **The lifecycle concept and the conformance row follow the predicate**, and
  the module note describes the new output. `writes:` gains
  `spec/concepts/lifecycle.md` — see the self-review.

- `delete:` (added by the review's fixes) the whole `GET /repos/{owner}/{repo}`
  request. Once the merge methods are read from the trunk's rule, nothing on
  the repository payload is used: one fewer round trip, one fewer parameter,
  and one fewer thing that can be wrong.
- `delete:` (added by the review's fixes) the `.slice(0, 10)` bound on the
  ruleset reads — an untested fixed number that truncated a bypass count
  silently. The reads run together instead, so the wall time is one request's.
- Net: 371 lines across the checker, its two suites and four documents.

#### Review

First read, a fresh context given this unit's diff and the two criteria — the
ladder and correctness — and nothing else. It confirmed the transition change
under mutation and found the forge read wrong in six ways. Each with its
disposition:

- `correctness:` the merge methods read from `allow_squash_merge` and
  `allow_rebase_merge` on the repository, when the ruleset's
  `allowed_merge_methods` is what governs the trunk — proved against the live
  API, where this repository's line claimed squash and rebase onto a trunk
  whose ruleset allows only `merge` — **fixed**, read from the trunk's
  `pull_request` rule.
- `correctness:` those toggles are absent from the payload without push
  access, so a read-only token read absence as enforcement — **fixed with the
  above**: the field is no longer read at all, and the repository request is
  gone with it.
- `correctness:` a ruleset the token cannot read was swallowed by
  `if (one.value)`, so a refused read printed *the forge enforces everything
  these records name* over a bypass list nobody had seen — **fixed**, a
  refused ruleset fails the whole read and names the status.
- `correctness:` `rules.find(…)` took the first `required_status_checks` rule,
  reporting a strict check as unenforced when a lax rule sorted first —
  **fixed**, strict if any applying rule is strict.
- `correctness:` `.slice(0, 10)` truncated silently, was untested, and is a
  fixed counter — **fixed**, removed; the reads run together instead.
- `correctness:` up to twelve sequential reads at 3s each could hold a
  blocking gate for ~36s — **fixed by the two above**: two round trips, the
  rulesets together, half a second against the live API.
- `correctness:` three branches and the whole of `githubRequest` had no test
  that fails when the behaviour is deleted — **fixed**, each now dies under
  mutation, `githubRequest` included, with `doFetch` as a parameter so the
  suite makes no network call.
- `correctness:` the host anchor of `githubSlug` had no spoofing fixture —
  **fixed**, three added, and the `i` flag with them.
- `correctness:` *Every run prints a third header line* is false under
  `--json` — **fixed**, the note names both shapes.
- `correctness:` the conformance row said *with no `ready` commit behind it*,
  which the predicate never reads — **fixed**, it says what the predicate
  does.
- `correctness:` `spec/concepts/lifecycle.md` still stated the removed edge as
  normative, and the step named no disposition for it — **fixed**, with the
  `writes:` widening recorded in the self-review above.
- `yagni:` the free-plan branch read `repository.plan.name`, which GitHub does
  not put on the repository payload — **fixed**, the branch is gone.
- `shrink:` a no-op override in a test assertion, and a defensive object copy
  — **fixed**, both cut.

Second read, a fresh context given only the diff of those fixes and the same
two criteria, as ADR-017 decision 3 bounds it. Four findings:

- `correctness:` merge methods were unioned across applying rules, and the new
  comment asserted that was right; GitHub applies the **most restrictive** form
  of a rule defined more than once, so they intersect — a ruleset allowing only
  `merge` beside one allowing `merge, squash` would have reported a squash the
  forge refuses — **fixed**, and the adversarial case the reader showed was
  missing is now there.
- `correctness:` `allowed_merge_methods ?? []` made an absent parameter read as
  the restrictive answer, where GitHub's default is all three — **fixed**, the
  default is the default.
- `correctness:` the comment on the slug fixtures claimed a loosened anchor
  would send the token elsewhere; it would not — the slug only ever builds an
  `api.github.com` URL — **fixed**, the comment names the real cost, which is
  reporting another repository's rules as this trunk's.
- `correctness:` the free-plan sentence stated a cause the code never read —
  **fixed**, the line reports the fact it read and invents no cause; the step
  says why the plan is not readable from what this reads.

The fixes above are not read a third time.
