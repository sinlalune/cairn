# CP-CAIRN-006 S03

### S03 — the seal everywhere, and two paths on the same files — **COMPLETE**

#### Plan

**ADR-002 decision 1, the seal at every transition.** `scope-digest` is
guarded by *a closed status on the path's own branch*, so a tick inside
an integrating commit on the trunk is never judged — which is how two
Crumbz paths were ticked at `done` under green runs. The guard widens to
every path record the change touches, whatever its status and whichever
ref carries it, the branch's own closed path still judged as today. The
fixture ticks a box at `done` on the trunk.

**ADR-003, two live paths on the same files.** A new advisory
`writes-overlap`: two live paths — `running`, `blocked` or `ready` —
whose `writes:` patterns meet, named with both ids and the patterns that
meet, raised at the registration of the later path and at every unit of
either, silent when either declares `depends_on` the other. Advisory,
because whether two paths may race on a file is the owner's call. Two
fixtures, one raised and one silenced.

Definition-of-done items advanced: the fourth and the fifth.

Type `implementation`: behaviour changes, so the failing tests come
first — the widened guard, the pattern-meeting predicate, the pairing,
and the three fixtures.

Deliberately not in this unit: ADR-004's six corrections (S04); one
commit for one path and the journal key (S05); the `review` rule, the
fixture sweep and the catalogue regeneration (S06). ADR-002 decision 2's
sentence in the path template and the open skill is path 1's and is
already written; ADR-003's sentence in `cairn-open` step 1 is path 1's
surface and outside this path's `writes:`.

- **The seal's guard widens.** `scope-digest` judged a closed status on the
  path's own branch; it now judges every path record the run's comparison
  sees changed, whatever its status, and still the branch's own closed path
  as before. A record carrying no acceptance yet — a draft, a registration
  landing in the same change — is bound to nothing *yet*, so the missing-digest
  branch stays where it always asked, at closure; so does the closing-record
  comparison.
- **`writes-overlap`**, advisory. `patternsMeet` decides whether two declared
  surfaces can name a common file; `writesOverlaps` pairs the live paths —
  `running`, `blocked`, `ready` — and drops a pair where either declares
  `depends_on` the other; the caller reports only pairs this run owns, the
  later path's registration or a unit of either. It is in
  `CLOSURE_RAISED_ADVISORIES`, because its value turns on other records and it
  must not be demanded of a candidate's attested set.
- **Three fixtures**: a box ticked in the integrating commit on the trunk; the
  overlap raised; the overlap silent under `depends_on`, with the declaration
  dropped again as its control.
- **The catalogue, the matrix and the soundness note** carry the new rule; the
  `scope-digest` row and the tools' module note say what the widened rule
  reads, and where a run's comparison bounds it.
