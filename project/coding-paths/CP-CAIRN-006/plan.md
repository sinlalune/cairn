# CP-CAIRN-006 — forward plan

Read when planning, never before every step. Each unit implements the
records its rule names and nothing else; a rule's fixture contains a
merged trunk commit carrying another path's unit (ADR-004 decision 4);
every refusal names its remedy in one sentence (ADR-008 decision 6).
Each unit runs the review movement on its own diff, as the unit skill
now says.

1. **S01 — the two debts, two records.** Type `decision`. ADR-024
   supersedes the clause of ADR-001 decision 1 on the kit's installed
   default: a repository installed at 1.1 declares `manual-git`
   registration, `pull-request` stays a schema value for a 1.0
   repository until `update` reaches it, and the skills path 1 wrote are
   coherent with the default; names `tools/cairn.mjs` (`init`, the
   transport option) and the configuration schema as path 4's surfaces.
   ADR-025 decides that a red run's post-mortem is read before the next
   unit, one sentence in `cairn-unit` movement 0 that path 3 writes with
   the tool. The 1.1 page amended in place, marked *since 2026-09-11* —
   *How a path opens*, the `cairn` tool row, *What 1.1 removes* — with
   the journal entry linked as *promoted from*; the architecture index;
   the ADR index; the register's rows 3 and 4.
2. **S02 — the profile line and the transition.** ADR-001 decisions 6
   and 7: every run prints what the forge does not enforce and the
   declared transports; `transitionErrors` loses `trunkIntegration`, a
   trunk commit from `running` to `done` with no `ready` commit is
   refused with its remedy, and the fixture is path 1's closing shape.
3. **S03 — the seal everywhere, and two paths on the same files.**
   ADR-002 decision 1: the scope digest judged at every transition, on
   every ref, against the acceptance in force; a fixture ticks a box at
   `done`. ADR-003: the advisory `writes-overlap`, silent under
   `depends_on`, at registration and at every unit.
4. **S04 — what the checker reads.** ADR-004 decisions 1, 2, 3 and 5:
   the registration commit as the activation, the remote checkpoint of a
   running path with a unit, path-scoped range rules, the branch resolved
   from where the checker stands. Decision 6: the three Crumbz repairs
   upstream — same-branch step supersession, chronological path-scoped
   provisional resolution, detached-checkout evidence.
5. **S05 — one commit for one path, one key, one remedy each.** ADR-008
   decisions 2, 4 and 6: the integrating commit refused when it is a
   merge object carrying the edit or takes two paths to `done`; the
   journal key `cairn.path` alone; every blocking message names its
   remedy. The stale citations of an earlier repository's records under
   `tools/` replaced.
6. **S06 — the review rule, the fixture sweep, the catalogue.** ADR-017
   decision 2: `review`, blocking, the current unit's step carries a
   non-empty `#### Review`, `closure` excepted. ADR-004 decision 4: every
   blocking fixture gains a merged trunk commit carrying another path's
   unit. The catalogue and the linkage on the conformance page
   regenerated, `tools/soundness.md` one line per new rule,
   `docs/modules/application.md` describing the tools as they are.
7. **S07 — the candidate.** Trunk merged in, gates bare, the request
   opened in the template's order; the administrative commit — `ready`,
   `subject_commit`, the checkpoint, the live view — on the branch and
   its check green before the owner is asked to merge, as path 1's
   journal says it should have been; the owner runs the checker on a
   repository of theirs before the merge.
