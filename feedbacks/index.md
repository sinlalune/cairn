# Feedbacks

Three kinds of note: what adopters hit in the field, read from their
repositories; the owner's pages to the protocol; and, since ADR-028, the
agents' files — what a writer met when the gate stayed green and the
protocol still cost more than it should, each observation with its cost and
the change to Cairn that would remove it. A note here is evidence for a
protocol change, never authority for one: it stays provisional until a
specification or tooling path promotes what it argues.

A note stays at this level while a release owes it an answer. When a release
has answered every ask it makes, it moves into `feedbacks/<release>/`, whose
index names what answered each — the owner's ruling of 2026-09-21. The notes
below are the ones 1.2 owes.

- [Treated by 1.1](./1.1/index.md) — the eight notes of 2026-09-03 to 2026-09-08: the two Crumbz post-mortems, the closure note, the sixteen-path audit, the owner's two feedback pages, the 1.1 decisions and the 1.1 rulings.
- [CP-CAIRN-009's writer — four things the gate could not see](./2026-09-15-cp-cairn-009-writer-feedback.md) — the first agent file, under ADR-028: a record naming a surface by a placeholder nothing resolved; one measured count restated in five documents and a register status hand-kept beside the records that carry it; a definition of done contradicting the record it cites; a record specifying a mechanism no release produces, with no way to mark it pending.
- [Crumbz updates to 1.1 — what the first `update` of an edited kit met](./2026-09-16-crumbz-update-to-1-1.md) — the writer of Crumbz's CP-CAIRN-UPDATE-027, under ADR-028: a repair the release had absorbed and a side-by-side reading that said it had not, with no page that names what a release absorbed; the live view always on the reconcile list while a path runs; a pointer page never pristine the day after; a file unmanaged at one reading and edited at the next; a close skill pointing at a file no release installs; template sentences that read false where they land; and, from the closing request's reviewer, a post-mortem tool that cannot count the run it runs in and prints a closed request as open, and on the trunk prints every path instead of the one that arrived.
- [Atomik adopts 1.1 — what the first `adopt` met in the repository the protocol was written in](./2026-09-21-atomik-adopts-1-1.md) — the writer of Atomik's adoption, as a field note and under ADR-028 where the gate stayed green: a `links` rule whose two 0.2 exemptions were deliberately left behind and ruled the adopter's own in CP-CAIRN-001 S06, which assigns that adopter work that cannot be done — a file its own header freezes, fixtures that must not resolve — and leaves a repository no way to declare an exemption but to fork the checker; a `status` that names a rewrite `update` will not make, on the one file an adopter's history is densest in; a folder of notes with no way to say which of them has been treated, with the owner's three options; an adoption that names the files it made stale without naming the consequence, leaving the repository's own CI red on the next push; and a kit that honours `roots.concepts` and derives the architecture, decisions and modules roots from the documentation root, writing a second architecture root beside the one the repository declared.

- [ECOS — the owner merges before the administrative commit](./2026-09-17-ecos-merge-before-administrative-commit.md) — the writer of ECOS's CP-R0-001, under ADR-028, on `pull-request` transport with one owner holding every role: the close skill puts the `ready` commit after acceptance and before the merge, and an owner who does what the skill says — read the pages, click merge — leaves that commit stranded on the branch, so `transition` refuses running → done and the writer repairs on the trunk; land it before the reading, or let the merge count as the approval.
- [ECOS — a deferral has nowhere to land](./2026-09-18-ecos-a-deferral-has-nowhere-to-land.md) — cairn-close and cairn-unit both require a deferral to name a follow-up and give the follow-up no home: a docs folder for durable knowledge, a log for what happened, a path folder that leaves attention at close, so three real deferrals were written three times each and read never; the ask is a `project/backlog/` folder, one file per deferred item, which the adopter has since built for itself in its CP-BACKLOG-001 — and not an issue tracker.
- [ECOS — checkboxes inside the text the scope digest pins](./2026-09-18-ecos-checkboxes-inside-the-scope-digest.md) — the path template writes the definition of done as `- [ ]` items inside the text `scope-digest` freezes, so the one gesture the notation invites is the one the rule forbids; it cost a `repair` unit that moved nothing in the product. Write the list plain, or normalise the box before digesting — and not a warning in the skill.
- [ECOS — the coherence questions ask the owner what an isolated reader should answer](./2026-09-18-ecos-coherence-questions-need-a-fresh-reader.md) — the four closing questions are all found by reading the diff against the repository and need the owner only to arbitrate, yet the `full` route hands them to the one person who did not read the diff, which is where a rubber stamp comes from; the unit skill's movement 4 already mandates a fresh reader for every unit, and the higher-stakes closing read has none. Make it a fresh-context read, with `cairn-audit` scaffolding what it can see — and not a checker rule.
