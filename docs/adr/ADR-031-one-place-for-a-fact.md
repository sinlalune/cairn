# ADR-031 — one place for a fact

## Context

Three facts of this repository each lived in more than one place, and
nothing reconciled the copies.

The kit's file count and skill count sat in the tools' module note, the
conformance page, the installer's header comment, a test and this
repository's README. Coding path 4 of 1.1 corrected them in four units;
each review found one more copy the unit had missed, and the count itself
moved twice inside the path. ADR-022 decision 2 had already made the
count a measurement and no target. Today the file count stands in the
conformance page's budget table — *33 and the lock on the `ci` profile,
32 on `local`* — and again in that page's kit row, the README and the
module note; the skill count, *six*, stands in the README, the module
note and the installer's header comment.

The roadmap register's State column said `running` for four paths whose
records said `done`. Path 4's writer named them in S06 and left them,
being outside the path; they were corrected by hand on 2026-09-16 in
`ae1c4b6`. `cairn-active` already derives the live view from the same
`status:` fields, and reads the register only for the advisory ADR-008
decision 5 added; every state cell is typed.

ADR-015 decision 2 has `update` print, beside the diff of an edited file,
the release's line on what changed in that template. No release writes
such a line. Path 4's S03 implemented the diff alone, which the decision
allows, and said so in a plan nobody scoping a release reads; nothing on
the record or the conformance page says the mechanism is pending.

## Decisions

### Decision 1 — a measured figure is written once and pointed at

Promotes **K03**, from Q3.

A measurement of the kit — its file count, its skill count, any figure
ADR-022 decision 2 made no target — is written in the conformance page's
budget table, one row per figure, and nowhere else. Every other place
that needs it links that row and restates nothing. The close skill says so in one sentence, where
it already asks whether the README lists a surface the path added.

What this changes, by today's names: `skills/cairn-close/SKILL.md`, the
paragraph on the README; the four restatements that stand today — the
kit row of `spec/reference/conformance.md`, `README.md`'s installation
paragraph, the tools' module note `docs/modules/application.md`, and the
header comment of `tools/cairn.mjs` — pointed at the budget row. The test
that checks the count compares the lock to the plan and pins no literal.

### Decision 2 — the register's state cells are generated

Promotes **K04**, from Q4.

`cairn-active`, which derives the live view from the path records, also
fills every cell of the roadmap register that states a path's state: the
State column of the milestone table, and the state a coding-paths table
writes beside a path. The cell is read from that path's `status:` and is
never typed; a row that names no path keeps what its author wrote. A
path's `status:` is the only place its state is written. The register
keeps its shape — the rows, the tables and every other column are the
owner's — and `cairn-active --check` reports a cell that disagrees with
the records as it reports a stale view.

What this changes, by today's names: `tools/cairn-active.mjs`, which
gains one write and one comparison beside the advisory of ADR-008
decision 5; `project/coding-paths/index.md`, whose state cells become the
tool's; the register template `tools/cairn.mjs` installs, whose one row
is the one `cairn-active` knows as `INSTALLER_ROW`; one test.

### Decision 3 — a record's implementation table may say *pending*

Promotes **K05**, from Q5.

Against a decision no path has landed, the implementation table carries
the word *pending* and the register row that owes the mechanism. The row
names the clause back. The path that lands the mechanism clears the word
in the unit that lands it. The checker does not read implementation
tables and does not start to.

The first use is ADR-015 decision 2's release line. This path's last unit
writes the word into ADR-015's table and the clause into the register's
1.2 row, when that row names the release path of 1.2 that owes it, and
the sentence into the shape section of the records' index. No coding path
is needed: the three surfaces are records and the register, this path's
own.

What this changes, by today's names: `docs/adr/index.md`, *Shape*, one
sentence; ADR-015's table, one word; the register's 1.2 row, one clause.

## Alternatives rejected

- **The agent corrects the copies it finds** (Q3, second option,
  *simplest*): refused by the owner.
- **The State column kept by hand, with a reminder in the close skill**
  (Q4, second option, *simplest*): refused by the owner. The fact is
  already derived once for the live view, and the reminder is the
  sentence path 4's writer had and could not act on outside the path.
- **A checker rule that refuses a state cell disagreeing with the
  record**: the tool that writes the cell makes the rule moot, and
  `--check` already reports a stale generation.
- **Deleting the State column, since the live view says it**: the live
  view lists live paths only; *done 2026-09-15* on a milestone is what a
  newcomer reading the register wants, and the register is the page the
  owner writes for them.
- **No word — the conformance page is where *not implemented* is said**
  (Q5, second option, *simplest*): refused by the owner. The conformance
  page says what a rule does not do, not what a clause of a decision
  waits for, and nobody scoping a release reads a unit's plan.
- **A status of the record, such as *partial***: the status vocabulary
  is the record's as a whole; the word names one clause.

## Consequences

- Each count is written once, in the budget table, and linked from the
  four places that restate it today; a count that moves is corrected
  once.
- The register's state cells cannot go stale, and a stale one is reported
  by the command that would fix it.

## What the manifesto's test weighed

Q4's option is tagged *adds a generation*: one more write by the
generator that exists, from the records it already reads, not a rule. Q3 and Q5 are a sentence and a
word.
