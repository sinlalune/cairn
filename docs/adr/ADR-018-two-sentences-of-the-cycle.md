## Context

Two things every cycle of 2026 has and the unit holds only in prose. Kent
Beck's rules for an agent — the simplest failing test first, the minimum
code to pass it, structural and behavioural changes never in one commit —
and the vendors' done-when that a machine re-checks: Codex goals, Claude
Code's evaluator and stop hook, Spec Kit's *converge* that reads the code
against the tasks after implementing.

On Crumbz, tests moved with the change in forty-eight of fifty-seven
source units, and one commit per unit says nothing about the order they
were written in. What separated the clean units from the rest was not the
order but the assertion: the units whose tests asserted a refusal were the
ones with nothing to cut. And nothing ticked in a definition of done was
ever machine-read; the coherence audit's four questions are Spec Kit's
converge in prose, answered by the writer at closure.

The owner answered on 2026-09-07: one sentence each, no step and no rule.

## Decisions

### Decision 1 — the failing test first when behaviour changes, no new test when only structure does

Promotes **Q8**, *One sentence* — one sentence.

A unit that changes behaviour writes the failing test before the change
and asserts the refusal it exists for; a unit that changes only structure
carries no new test and says so in its plan. The unit skill says it where
the change is made. No commit is added and the order leaves no trace in
the history; the sentence is an instruction to the writer, and the test's
assertion is what the reader of ADR-017 sees.

This is where the second half of the size rule ADR-016 refused with Q3
returns, as a sentence on the test: it does not bound the unit.

What this changes: the `cairn-unit` skill, step 2, one sentence.

### Decision 2 — the request answers the definition of done item by item

Promotes **Q9**, *The request answers it item by item* — one sentence.

The request's description — the coherence review of the candidate — opens
its coherence section with one line per item of the definition of done,
each naming the unit that advanced it and the command or page that shows
it done. The lines are printed from the record for the writer to fill.
Nothing ticks a box: the checkboxes of the record stay as ADR-002
decision 2 left them, and the digest still seals them. The lines are read
by the owner before the merge, and by nobody by machine: that is the
page's third option, refused below.

What this changes: the `cairn-close` skill, step 2, one sentence; the
request template, `.github/pull_request_template.md`, generated by
`requestTemplate` in `tools/cairn.mjs`; `tools/cairn-audit.mjs`, which
prints the description's shape and gains the lines from the definition of
done; `tools/cairn-audit.test.mjs`.

## Alternatives rejected

- **Q8, no** (simplest, as today): tests move with the change and assert
  the refusal; the order is the writer's. Refused for one sentence that
  costs nothing.
- **Q8, a test-first movement** (adds a step): the failing test pushed as
  a provisional commit before the change, two commits per unit. Refused:
  no record could prove the order, and the evidence says the assertion
  mattered, not the order.
- **Q9, no** (simplest, as today): the plan names its item and the owner
  reads the request against the list.
- **Q9, each item names its check** (adds a rule): an item names a command
  or a test the checker runs at the candidate, refusing one whose item
  fails. Refused: a done-when the machine reads costs a rule and items
  that can be written as commands, and a documents-only path has none.

## Consequences

- Two skills gain one sentence each; the audit tool and the request
  template gain a list they derive from the record.
- The owner's read of a request starts from the definition of done, item
  by item, instead of from four questions about the diff; the four
  questions follow.
- A unit's plan says which of two kinds it is, and a reader who finds a
  behavioural change with no new test knows what to ask.
- No fixture: neither sentence enters the checker.

## What the manifesto's test weighed

Decision 2 gives the owner the converge every product has, in prose,
once, at closure, at the cost of a list the tool already has the data to
print. Nothing enters the checker.
